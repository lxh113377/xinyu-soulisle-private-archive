## 0. 结论摘要（先看这一段）

1. **本质**：回声不是「噪声」，是**另一路合法语音**——频谱、韵律、能量与用户发言同源，靠信号特征**无法**区分。因此「检测与区分」的唯一出路 = 利用系统自知的信息做交叉判据：**时间（播放窗口）+ 内容（念白文本）+ 状态（播放状态机）**，即「三把尺」。
2. **本栈约束（诚实声明）**：心屿现行识别走 Web Speech API（浏览器内部采集）——JS 层既**管不到识别流**、也**拿不到播放参考信号** ⇒ **真正的 AEC（回声消除）在当前链路不可自控**，不要在此投入工程预算；AEC 的真实入场条件是「自建采集 + 自建 ASR + 自建 TTS 三件同迁移」（P2，登记触发条件，见 §6）。
3. **现状**：wb-echo-L0（`3d81d72`，2026-10-13）已落「识别结果过滤」面主防线（准入闸 + 尾音软窗，C16 16/16）；「播放状态标记」面部分在位。剩余缺口 5 项（playLog 时间窗 / duplex 切换冷却 / N 句环形缓冲 / barge-in 能量突增判据 / AEC 登记），见 §6 缺口表。
4. **治理总纲**：**四道防线叠加，禁依赖单一判据**（继承 GM `lessons.part567` 的「三道闸 + 三把尺」）——① 音频采集抑制 ② 播放状态标记 ③ 回声消除 ④ 识别结果过滤。

## 1. 现象与危害

### 1.1 现象定义
自听（self-listening）/ 声学耦合回环：**TTS 念白 → 扬声器 → 空气/机身传导 → 麦克风 → ASR 转写 → 被当作「用户发言」→ 进入对话链路 → 触发基于错误输入的回复逻辑**。在级联语音管线（VAD→ASR→LLM→TTS）中形成闭环，严重时自激（自问自答）。

### 1.2 危害链（按产品严重度降序）
1. **危机误触发（最重）**：念白含危机词被回读 → 误触危机转介逻辑 —— 对心屿这类情感陪伴产品是安全级事故面；
2. **自激循环**：回复 → 回读 → 再回复，答非所问 + LLM token 翻倍浪费；
3. **自己打断自己**：全双工 barge-in 把念白拖尾当「用户插话」→ 中途闭嘴、断句；
4. **重复回答 / 语义漂移**：念白残句拼进用户下一句（C11 与 wb-echo-L0 修的就是这一类）。

### 1.3 心屿一手实测形态（wb-echo-L0 前）
- 排水（念完转回听态）后，念白回读污染 `pending`，620ms 后被语义收句判为「完整句」而提交——C16 旧码先验红 `texts 6→7`；
- 半双工/恢复窗口内，`bargeIn()` 可被念白触发（判定只看「非回声文本 + ≥2 字」，无能量判据）。

## 2. 成因分析（五层，逐层回答「为什么没拦住」）

### 2.1 物理层 · 声学耦合不可避免
扬声器 → 麦克风之间：直达声 + 空间反射（混响）+ 机身结构传声。外放场景信噪比最差——**回声与用户语音同量级**，且人无法要求用户戴耳机。

### 2.2 信号 / 采集层 · 没有可控的 AEC 面
- **两路采集分离**：ASR 走 Web Speech API 内部采集（`webkitSpeechRecognition`，JS 层无 PCM、无参考）；音量计走自建 `getUserMedia` 流——`AUDIO_CST = {echoCancellation:true, noiseSuppression:true, autoGainControl:true}` **只作用于音量计这一路**（voice-call.js L41 注释原文即此声明）；
- **无参考信号**：`speechSynthesis` 播放拿不到输出 PCM ⇒ 无法自建「参考信号 - 自适应滤波」的 AEC；
- **AEC 双讲断崖**：即便有 AEC，近端（用户）与远端（念白）同时说话时自适应滤波器难收敛，回声残留上升（lessons.part567 原因①）；
- **AGC 双刃剑**：自动增益会把回声一起放大。

### 2.3 检测层 · VAD「认能量不认来源」
机器人语音**本质就是语音**：能量、频谱、韵律全部像「人在说话」，VAD/端点检测无来源概念；分句朗读的**句间停顿**还会制造「语音起止点」假象，让下一句念白被当成「新发言起点」。

### 2.4 逻辑层 · 播放与识别无联动（这是本域真正的洞）
wb-echo-L0 前：无播放窗口标记、无冷却期、转写直通 `pending`；状态机（idle/listening/thinking/speaking）只服务 UI 与半双工切换，**不参与识别准入**。

### 2.5 闭环层 · 环路延迟决定自激强度
「播放→拾取→识别→提交→生成→再播放」环路若短于收句停顿阈值（SILENCE_MS=620ms），回读会在每次停顿处稳定触发 ⇒ 连续误回复。延迟越小、音量越大，自激越强。

### 2.6 心屿特化 · 两条 TTS 路径的参考信号差异（关键差异表）

| TTS 路径 | 用什么播 | 能否拿到参考信号 | AEC 可行性 |
|---|---|---|---|
| 浏览器 `speechSynthesis` | 系统合成 | ❌ 无 API 可取 | ❌ 不可做 |
| 本机神经引擎 sidecar（`ltSpeak`） | `fetch /tts` → WAV blob → `Audio` | ✅ **WAV blob 即参考信号** | ✅ 可做（P2） |

> 结论：这也是 lessons.part567 给出「选本机引擎的理由 +1」——本机 TTS 路径天然把 AEC 的门留开了一条缝。但注意：AEC 消除的是**采集流**里的回声；若 ASR 仍走 Web Speech（另一路采集），AEC 等于白做 ⇒ 必须「自建采集 + 自建 ASR」同迁（§6 P2）。

## 3. 检测与区分方法（判据全集）

> 原则：**禁依赖单一判据**。单一判据必有两类失误——放行（漏杀回声）或误杀（把真话当回声）。多判据交叉 + 对照腿守误杀面，才成立。

| # | 判据类别 | 原理 / 判定式 | 当前栈可获取性 | 心屿现状 |
|---|---|---|---|---|
| 1 | **时间判据** | 播放窗口 `[t0, t1]` + 尾音窗 δ（余响+管线延迟，取 200–600ms）；窗口内严查、窗口外放行 | ✅ 可获取（自记时刻） | ✅ 部分实现：`speakEndAt + TAIL_MS=600` 软窗；❌ 缺结构化 `playLog`、缺 duplex 切换冷却 |
| 2 | **内容判据** | 转写归一化（去空白/标点）后与最近念白文本比对：精确互含 → 模糊相似（字符 bigram Dice / 编辑距离），阈值分软硬窗 | ✅ 可获取（念白文本自持） | ✅ 已实现：`isEchoFuzzy`（0.6 常规 / 0.45 尾音窗）；❌ 缺最近 N 句环形缓冲（现仅上一句 `recentSpoken`） |
| 3 | **状态判据** | 播放状态机（idle/listening/thinking/speaking）联动准入；半双工 `pauseRec` | ✅ 已具备 | ✅ 状态机在位、半双工已用；❌ 状态迁移无延迟（切 full 立即 `resume()`） |
| 4 | **能量判据** | barge-in 能量突增：相对播放前基线 ≥2× 且持续 ≥300ms（+ 与念白弱相似）——把「真打断」与「念白拖尾」分开 | ⚠️ 可获取（`lvl` 音量计；取不到时降级放行） | ❌ 未实现（barge-in 现只看文本） |
| 5 | **说话人判据** | 声纹比对：输入片段 vs 注册用户声纹，相似度低 + 与 TTS 音色相似 → 回声 | ❌ 当前栈不可得（无音频样本出口） | ❌ 登记 P2 |

**组合判据（三把尺的具体用法）**：
- **真打断三条件**：能量突增（≥2× 基线、≥300ms）∧ 与念白文本弱相似 ∧ 是完整语义 —— 三条全中才放行打断；
- **回声丢弃**：时间窗命中 ∧（精确互含 ∨ 模糊 ≥ 阈值）—— 丢弃时**必须同步推进消费位**（`baseLen = lastLen`），否则被丢的残句会拼进下一句（wb-echo-L0 一手教训）；
- **禁「硬拦转写」**：尾音窗内只能**放宽阈值**（0.6→0.45），不能一刀切拒绝——硬窗会误杀真人快答且打不中单发转写桩（C11/C14 一手抓出）。

## 4. 治理方案（四道防线全景）

> 与题面四类手段一一对应：音频采集抑制 = ①、播放状态标记 = ②、回声消除 = ③、识别结果过滤 = ④。

### 防线① 音频采集抑制（采集侧）
- **手段**：半双工 `pauseRec`（讲完再听）；`getUserMedia` 三面旗显式声明（仅音量计路）；产品侧耳机引导 / 音量管理；硬件侧麦克风阵列波束成形（远期）。
- **心屿现状**：半双工已实现（`duplex=half` 开口即停识别，C8b 判据在案）；三面旗已实现（C12）。
- **局限**：半双工牺牲「可随时打断」体验；对默认 `full` 无效——所以不能当唯一防线。

### 防线② 播放状态标记（播放侧 · 当前最该补强）
- **已实现**：状态机 + `speakEndAt`（队列空即记时）+ `recentSpoken`（bargeIn 时把当轮念白转存作跨句比对）+ `TAIL_MS` 软窗。
- **建议补（见 §6）**：① `playLog [{text, t0, t1}]` 环形日志——跨句回读的结构化依据；② duplex 切回 `full` 延迟 ≥300ms 再 `resume()`——防「刚开双工就把残留念白收进来」；③ 分句队列的空窗期管理（句间停顿纳入播放窗口语义）。

### 防线③ 回声消除（信号侧 · 诚实分级）
- **现行 Web Speech 路径：不可做**（无采集控制权、无参考信号）——不要在此花预算；
- **本机 TTS 路径（`ltSpeak` WAV blob 可作参考）：可做（P2）**——`AudioWorklet + WebRTC AEC3(wasm)` 自建采集管线；
- **入场条件（三件同迁）**：自建采集（gUM 原始流）+ 自建流式 ASR（本机已有 `local-asr` [Qwen3-ASR/OpenVINO，文件级]与 `local-tts` [sherpa-onnx sidecar]两条能力线，流式 ASR 是缺口件）+ 参考信号路由——**三缺一都不立项**；
- **采集参数提示**：`echoCancellation` 在自建流上真正生效；`autoGainControl` 需权衡（压制回声 vs 用户小声可闻）。

### 防线④ 识别结果过滤（识别侧 · 已落，继续加固）
- **已实现（wb-echo-L0）**：`onresult` 准入闸 `isEchoFuzzy`（精确互含 + 2-gram Dice 滑窗，0.6/软窗 0.45）→ 命中即丢弃并推进消费位；`commit` 前二次校验；`bargeIn` 念白转存 `recentSpoken`。
- **建议补**：N 句环形缓冲（跨 2+ 句回读）；与 `playLog` 的**时间 ∧ 内容双因子**联合判定；短碎片（<200ms / <2字）与低置信度过滤（可选）。

### 打断策略专节（全双工 ≠ 放行一切）
- 现状：`state !== "listening" && duplex === "full" && got.length >= 2` → `bargeIn()`（通过回声过滤后）；
- 目标：三条件收紧（能量 ≥2×基线 ∧ 持续 ≥300ms ∧ 非回声文本）；能量读数取不到时**降级放行**（保持现有语义，宁漏勿误）。

### 优先级总表

| 优先级 | 项 | 状态 |
|---|---|---|
| P0 已做 | 准入闸 + 尾音软窗 + 丢弃推进消费位 + commit 二次校验（wb-echo-L0，C16 16/16） | ✅ |
| P0 待做 | `playLog` 时间窗 / duplex 切换冷却 300ms / barge-in 能量突增判据 | ⬜ |
| P1 | N 句环形缓冲 / 指标化（误触发率、误杀率） | ⬜ |
| P2 | 声纹判据 / AEC3 架构（自建采集+ASR+TTS 同迁） | ⬜ 登记 |

## 5. 验证与回归（怎么证明「堵住了」）

1. **判据模式（C16 为范例）**：先验红后验绿（旧码先跑出 `texts 6→7` 再修）+ **对照腿**（异文真话必须照常提交，防「反正都不收」的空靶）+ 三个边界全桩化（SpeechRecognition / speechSynthesis / getUserMedia 受控）。
2. **建议新增腿**：
   - C17 跨句回读：连续 2–3 句念白回读全部丢弃；
   - C18 能量突增真打断：高能量异文 → 打断生效；念白拖尾（高能量但相似）→ 不打断；
   - C19 尾音窗边界：δ 内严查、δ 外正常放行（对准 ±50ms 边界）。
3. **指标定义**：误触发率 = 回声触发轮次/播放轮次数（目标 0）；误杀率 = 真话被丢/真话总数（对照腿守）；打断延迟 P95；**首声延迟回退量 = 0**（软窗设计保证不增延迟）。
4. **人测项**：真麦 + 外放音量 80% 连续 30 分钟（机器只压结构，真机归人测——C14 既有口径）。
5. **证据链**：每轮保留（录音 + 转写 + 播放日志）三元组，供误触发回放定位。
