## 2. 逐项差距说明

### ① 功能：向量长记忆 7/16（不立项，重申）

SillyTavern（9 向量提供方 + vectra）、opensoul（sqlite-vec + hybrid + qmd）、letta（pgvector + MemFS）三方印证：向量召回是陪伴/Agent 类最强扩展生态。r88 已评估：单用户演示场景两表 + 扩展缝文档化够用。本轮点采未改变前提 ⇒ **维持不立项**，触发条件不变（多用户长期记忆 / 评委问语义召回 / 需 RAG 答辩点）。

### ② 实现：opensoul 的测试/行数守卫（新可借鉴，中优）

今日点采新货：opensoul `vitest 五配置（unit/e2e/gateway/extensions/live）+ pnpm check:loc（文件≤2000行/函数≤150行）`。对照 self：已有 `size_budget`（逐文件字节预算）+ 行为 Core P0.8（函数≤50行）+ 112 套件。差距不在"有没有数"，而在"有没有把行数/函数长这两把尺钉进 CI 门"。本轮记 P1（见 §3 #4），不直接上——上之前先量两侧边界（R236 补注③），且前端零构建形态下加新 CI 门有稳定性成本。

### ③ 实现：lint 门 0 vs 1/16（维持不执行）

SillyTavern（eslint）仍是 peers 唯一领先 self 的一格。r91 已登记 P1：前端零构建经典脚本 + window.X 挂载形态下 no-undef 误伤面大，不拿 CI 稳定性换这一格。本轮点采（opensoul 另有 lint 但属 pnpm 生态）未改变结论 ⇒ 维持，触发条件不变。

### ④ 维护口径：letta 跟踪地址必须换（本轮纠正）

点采证实：`letta-ai/letta` 现仅 landing 页（CI 只剩 Issue Guard + dependabot），V1 Python 已归档，权威实现迁 `letta-code`（TS/Bun）。r91 台账记 letta ★24,994 / wf 等数字若继续沿用旧地址采样，会把"迁仓"误读成"停更"。处置：下轮 `benchmark_metrics` peers 名册把 letta 行换到 letta-code（记 §3 #5 P1），本轮先书面纠正，不动判据代码。

### ⑤ 架构对照：MoodChat Spring 同构（已对账，无动作）

MoodChat：Java17 + Spring Boot 4.1 + Spring AI + MyBatis-Plus + Spring Security + JWT + MySQL，前端另仓，无容器、无 workflow、无向量表、单测试空壳。我方：Spring Boot 3.2.5 + 轻量 token 过滤器（Security 已按决策 #4 否决）+ H2 file/MySQL 可切 + 112 套件 + 双门。结论：同构对照下我方工程化（测试/门禁/部署）全面领先；对方仅在"Security + JWT 多用户"一格有配置，我方是**有意不做**（单团队演示），不构成差距。
