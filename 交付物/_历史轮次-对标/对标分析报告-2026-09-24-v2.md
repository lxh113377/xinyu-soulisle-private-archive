## 4. 逐项差距说明（七维，含本轮消除情况）

### 4.1 功能模块覆盖
- **实测差距**：流式输出（A/B 层 3 家全有，心屿无）、TTS（OLV/Lobe/my-neuro 有，心屿只有 ASR）、多供应商（A 层全有，心屿只有 DeepSeek 硬编码 env）、角色/persona（SillyTavern 角色卡、my-neuro 自定义人设）。
- **心屿反超项（应保持并写进答辩）**：**危机转介 14/14 家缺失**；**73 条可现场复跑的情绪评测 + JS↔Java 逐项对账** 14/14 家缺失；**逐句情绪着色的 3D 可视化 + 刷新后重放** 无一家同构。
- **本轮**：流式 / TTS / 多供应商 → ✅已落地（`stream_contract.py` A/B/C 全 PASS、`ux_guards_check.py` U1 PASS）。persona 与语义记忆 → 计划 #4。

### 4.2 技术架构与实现方式
- LobeChat（Next.js + Zustand + Drizzle + PG，98.7% TS）与心屿（零构建原生 ES Module + Spring Boot 直读 `src/`）**不是同一条路线**。首轮判定"这是选型不是缺陷"，本轮复核仍成立（决策 #1/#2 已记五要素）。
- **真正该抄的是抽象形状，不是框架**：provider 注册表（统一 `/chat/completions` 出口）、策略/提示词配置化。两者本轮都已落地，**成本远低于换栈**。
- **仍存在**：无 DI/组件化的前端在 `app.js` 已 380+ 行，编排/渲染/TTS/曲线/设置混在一个 IIFE → 建议赛后按 `voice/tts/chart/window` 拆 4 个模块（不改行为，纯切分）。

### 4.3 性能表现
- **已修**：首字延迟（流式后从"等整包 1.5s"变为"首帧即出"，实测 SSE 30 个内容帧）、长会话 DOM 上界（60 条，U2 实测）、移动端粒子（900/1200/2600 三档，U3 实测无横向溢出）。
- **未修（诚实登记）**：`tick()` 每帧仍遍历全部粒子做 CPU 侧着色（2600 次/帧；降档只在小屏生效）；无 FPS 面板与真机帧率实测 → **❌未实测**，不进 CI。
- **无差距项（实测）**：首屏零构建直开、WebGL 不可用降级 CSS、LLM 不可达 3–11ms 回落离线。

### 4.4 可扩展性
- **本轮主要收益维**：情绪策略表 SSOT（`src/data/emotion-strategy.js`）+ 词表 SSOT（首轮 e79025b）→ 现在**加一种情绪 = 改两个纯 JSON 文件，代码零改动**，且 `_test/strategy_check.py` 会在只改一处时**当场 FAIL**（`--selftest` 已注入分叉证明判据非恒真）。
- **仍落后**：无插件/扩展机制（判定为不做，见 §6 低优先），共情链路顺序仍固定在代码里（识别→策略→生成），不支持声明式 pipeline。

### 4.5 维护状态
- **心屿**：27 次提交、每日活跃、判据全绿。
- **对标教训（实测数字）**：OLV 13,898★ 却 **2026-05-15 起零推送**（4 个月）；Loyal-Elephie 352★、2025-02-28 停更（19 个月）。**热度≠可持续**。
- **本轮补齐**：`ROADMAP.md`（含**明确不做**及理由）+ 语义化版本（`server/pom.xml` `0.1.0-J1` → **`1.3.0`**）+ CHANGELOG 1.3.0 条目 + **`v1.3.0` 标签**。
- **仍缺**：贡献者数 1（团队 5 人但提交集中一人）→ 提交规范已写进 CONTRIBUTING，需队友实际提 PR 才成立。

### 4.6 文档完善程度
- **本轮前**：README 双语 / CONTRIBUTING / SECURITY / CHANGELOG / .env.example / Issue+PR 模板已具备（首轮 H1–H7）。
- **本轮新增**：`ROADMAP.md`、`.env.example` 的 `LLM_*` 与"哪个平台不支持流式"说明、CONTRIBUTING 第 5 条红线、README 功能表 6 行新能力 + 验证段扩到 7 条命令。
- **横向定位**：A 层（LobeChat）7/7 文档项齐；心屿现 **7/7**；14 个垂类同类项目里 **同时具备 CHANGELOG+CONTRIBUTING+SECURITY+.env.example 的只有 2 个**（`NJX-njx/opensoul`、`s-nagaev/chibi`，均 ≤60★）。→ 结论：**文档齐备度不是体量问题，是意愿问题，心屿已在第一梯队**。

### 4.7 适用场景
- 心屿（高校情绪倾诉 / 独居青年，Web 免安装）与 A 层（通用工作台/桌宠/角色扮演）、C 层（论文原型 / 本地 agent）**场景不重叠**；14 家全部无"医疗免责 + 危机转介 + 降级明示"三件套。
- **答辩可直接引用**：「对标 14 个同类开源项目，危机干预实现数 = 0；可复现情绪评测集数 = 0」——这是创新分（30）与技术分（30）的实证，不是话术。
