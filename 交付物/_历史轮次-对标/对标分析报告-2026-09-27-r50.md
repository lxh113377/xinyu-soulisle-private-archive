## 2. 逐项差距说明

### 2.1 🔴 高｜漏洞告警整条是关的，而所有"看文件"的检查都看不见（已闭合）

✅ 实测开轮时：`gh api repos/{slug}/dependabot/alerts` →
**`Dependabot alerts are disabled for this repository.`（HTTP 403）**；`GET /vulnerability-alerts` → 404。
与此同时 `.github/dependabot.yml` 自 r21 在册、也确实开出过 4 张 PR ⇒
**"配置在 + 有 PR"给人的印象是"依赖治理已覆盖"，而真正的 CVE 通道是断的**：出漏洞时连平台都不通知。

处置与证明（不写"应该已开启"）：`PUT /repos/{slug}/vulnerability-alerts` → 204；
`GET` 由 404 变 **HTTP 204**；alerts 端点由 403 变可读、**当前告警数 0**。

⇒ 顺带修正我自己的一个判断：我此前评估"要不要升 Spring Boot 4"只按技术债/回归成本算，
漏了"有没有已知 CVE 压力"这一格 —— 现在有了平台答案（0 告警），"不升"在截止日前是**有依据的**决定。

### 2.2 🔴 高｜一张结构性不可能合并的自动 PR 挂了 6 天（已闭合）

PR #2 `spring-boot-starter-parent 3.2.5 → 4.1.1`（09-24 开出）：`Java 服务端构建` 30s fail、
`浏览器回归` 56s fail ⇒ 它永远不会绿。而同期另两张 **major** —— `actions/checkout 4→7`、
`setup-python 5→7` —— **已正常合并**。⇒ 结论不能写成"major 危险"，只能是
**Spring Boot 跨大版本属于需人工评估的迁移**，不该由自动直送。
已给 maven 加 `ignore: 大版本`（**actions 不扩面**，因为它无此症状），并带证据关闭 #2。

### 2.3 🟡 中｜"在册·行为未证"这一类没有出口（已闭合）

`NJX-njx/opensoul` 有 `dependabot.yml` 但行为面 NA；本仓若只看配置文件也会得出同样的虚高。
探针与判据现在都要求：**未取到 ≠ 零**，NA 有自己的形状与计数（`usable + NA == total` 自证打印）。

## 3. 本轮我自己被抓到的（五条，其中三条是"度量学"）

1. **org 级配置让声明面假阴性**（lobehub 案例，见 §1）。我第一版把"dependabot 件 1/16"当成
   "只有 1 家挂了 dependabot" —— 真数是 2 家有行为证据。**猜的方向还反了**（我以为挂配置的会比跑得多）。
2. **search 端点的 secondary rate limit 造出过一个假结论**：首版走
   `search/issues?q=author:app/dependabot`，单次成功后续即 403（同请求走 `gh api`/core `/pulls` 都 200），
   16 仓里 15 个 NA ⇒ 汇总行据此打印 **"配了 dependabot 的 1 家里真跑过的 0 家"**。
   这一句当时看起来完全合理，且正好支持我的叙事（"我们比对手强"）。改走 core 端点 + 按 `Retry-After`
   退避后 NA 14→5，结论变成"2 家有行为证据"。**没有那一步，这条会被原样写进报告。**
3. **我的 `throttle()` 从来没生效过**：每次调用先 `del CALLS[:]` 清空历史，再拿空列表算"最近调用"
   ⇒ 永远判定不限流。这才是换端点后仍全 403 的真因。
   我在定位它之前先给了两个解释（"权限不足"、"间隔不够"），**两次都被实测否证** ——
   第三次才去读原始报错（Bearer 单发 200/44，同 token 连续发即 403 + 文档链指向 secondary limit）。
   教训：归因要读工具自己吐的原文，不要拿"最像的解释"接力。
4. **`verdict()` 把 NA 塌缩成"无回执"**：`if beh.get("opened")` 对 `None` 与 `0` 同假 ⇒ 两者都掉到
   "在册·行为未证"。修完补反例 E 钉住（`opened is None` 必须产出 NA 形状，不得出现"零"字样）。
5. **G8 顺序又漏了（连续第二轮）**：r47 补写过一次，本轮又是先写代码再补推演块。
   两次说明"靠记忆执行动手前推演"不可靠 ⇒ 已在 DAG 块首行写下机制性改法：
   **宣布轮次后的第一个工具调用就是 `dag_precheck --require-mark`**，而不是等想起来。
