## 2. 逐项差距说明（本轮五处一手发现，全部可复算）

### 2.1 工作树门禁看不见提交面（高，维度 3/7）
见 §0。表现是"昨天的活儿在远端不存在而本地全绿"，实质是**判据取数面选错**。
复算：`git ls-tree -r HEAD --name-only | grep -cE "perf_ramp_delta|timing_coupling"` 应为 **2**（本轮已入库）。

### 2.2 阶梯并发曲线的"无塌方点"落在仪器自己的噪声带里（高，维度 4）
本轮同机静置实测（`perf_baseline_check.py` 连测 5 轮，取每档 rps 的 max/min 带宽）：

| 采集口径 | 各档带宽（health/emotion 混合，8 条面） | 备注 |
|---|---|---|
| `work_per_thread = 4`（r96–r98 用的） | 13.5% / 42.1% / 43.0% / 69.4% / 117.7% / **255.8%** | 首轮冷启 8 线程档 = 986.6 rps |
| `work_per_thread = 32`（本轮起） | 9.2% / 15.6% / 16.9% / 26.0% / 29.6% / 31.9% / 33.9% / **38.4%** | 收窄 6.7 倍（按最坏值） |

后果链：每档总请求只有「档位 × 4」（t8 = 32 个请求、`took_s` ≈ 0.01s）⇒ 两次读数的差主要
来自这台机器此刻在忙什么。同日相隔 30 分钟的两份台账实测最坏 **−40.1%**，**当场踩穿 40% 阈值判红一次，
而什么都没坏**。于是 r96 写的「吞吐在 ~2.0k–2.6k rps 区间平台波动、8→64 没有塌方点」这句话
（以及 `published_numbers` 这一格"我们领先 16/16 全行业"的读数）**不能被继承成容量结论**。

处置：修仪器而不是放宽判据——口径提到 `work=32`、阈值按实测带宽定 **50%**、
并加**口径腿**（`work_per_thread` 或档集不同 ⇒ rc=2 UNVERIFIED，新旧台账不得互比）。
检测限如实写进文档：**只能检出 ≥50% 的档内回退**，30% 量级检不出；要更细的正解是每档重复取中位数（r100）。

### 2.3 文档里的"条数"没有机器责任方（中，维度 7）
`ledger_age` 文档写 `--selftest 27 条`、实测 32 条，漂了一整轮，G16 旧三面谁都看不见
（它只核脚本名在不在）。本轮实测口径：全仓只有 **7 件**脚本自报 `N/M 条`，而文档有 **14 处**手写
⇒ "跑一遍 --selftest 对账"覆盖不到一半，且有把 pre-push 20s 预算顶穿、拖累他人提交的风险，**否掉**。
落地口径改为二选一：改指针（「条数由脚本自己印」，先例见 r90 那两行）或标明「当日值」。
不一刀切禁数字——本仓规矩是被推翻的原文要留着加更正注，禁数会逼作者删历史。

### 2.4 判据自己写的"验收标准"可以按构造不可达（承 r98 §2.1，本轮再落一次）
本轮新形态：**完成态等待有两种看起来对、实测必等的写法**。改 `ux_guards_check` 时我先写
「`[data-emotion]` 气泡数 +1」，U2e 等满 15s——窗口化从 `#chat-log` **顶部**裁气泡，
展开后再发一条时总数是**下降**的；改写成「先等最后一条是 user 气泡再等它变 AI」又等满 8s——
离线模板 ~3ms 就回完，**中间态在第一次轮询之前已经过去**。终版用身份章（点提交前给当时
最后一条盖章，之后等"带 data-emotion 且无章"）。教训：等"计数变化"和等"中间态"都不是完成态，
要等**这一轮自己的终态**。

### 2.5 peers 侧本轮 0 新增读数（方法论，与 r96/r98 同款）
本轮新增判据全为零网络；同轮 burst 重采 12 探针在 r96 实测撞 GitHub secondary rate limit
（`peer-community` 5 行返回 403）。**代价如实记**：维度 1/3/7 的 peers 列与 r95 同源。
16 族台账 `ledger_age` 现测全在 fuse（7 天）内，**超龄点约 10-12** ⇒ 错峰重采已列为 r100 第一入口。
