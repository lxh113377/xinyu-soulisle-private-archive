### 2.2 技术架构：SSOT 是本轮能「一次改对两端」的原因

本轮改造一同时改了 JS 与 Java 的否定判定，**两侧同时从 98.6% 变 100%**，且 `engine_consistency_check`
报「词表 + 逐条预测 + 汇总指标全等」。这不是运气：词表是**唯一真相源**（决策 #6/J6 结构），
两端不允许各存一份。对标池里 `deps_autoupdate` 只有 2/16，本质是它们**没有需要跨端同步的单一数据源**。

**可借鉴点**：lobehub 的 `apps/` + `packages/` 分层（tier A，29.73 commits/日）值得学的是
「把可复用件下沉为包」——我方对应动作已部分完成（`server/` 分层 + `src/data/` 数据下沉）。

### 2.5 可扩展性：记忆与多语言维持不立项

## 5. 本轮落地回执（随改造推进实时更新）

### 5.1 改造一 · 双核心能力增量（H1 + H2）— ✅ 已完成

**排序依据**：用户 2026-10-11 立规「表情识别·语意理解 = 每轮第一要务」；评审创新 30 / 技术 30 直接看这两项。
**执行顺序**：先加数据 → 再改模型 → 两端同步 → 复算锁基线。

| 步 | 动作 | 回执 |
|---|---|---|
| ① | 评测集加 4 条远距离否定 + 2 条防误伤对抗 | 73 → **79** 条；改模型前复跑 = **97.5%，新增 4 条全错** ⇒ 数据有证伪力，不是空跑 |
| ② | 否定取词窗口 3 → 4（JS `NEG_WINDOW` / Java `NEG_WINDOW`，具名常量） | 修复 4 条，但**新踩 2 条**：「解释也【没】人信，愤怒」「什么都不【不】懂，好慌」——否定词与情绪词隔着逗号 |
| ③ | 加 `NEG_BREAK`：否定词与情绪词之间隔标点/空白 ⇒ 修饰关系不成立 | 2 条误伤消除，**79/79 = 100%**，危机 6/6，misses=0 |

| ⑤ | Java 侧构建期锁同步（原写死 73 / 98.6% / misses=1） | `EmotionControllerTest` 更新为 **79 / 100.0% / 0**；`mvn test` **101/101 BUILD SUCCESS** |
| ⑥ | 双端一致 | `engine_consistency_check`：**JS 79 = Java 79，100.0% = 100.0%，危机 6/6**，词表逐项全等；`--selftest` 注入分叉能报出 ⇒ 判据非恒真 |

**过程中的一手发现（两条，都值得记）**：

1. **扩窗口必然引来误伤，必须先想清楚「什么不算否定」**。首跑就踩中 2 条跨标点误伤。
   教训形态与 r110 的「透明度不能用同一档治所有状态」同族：**全局参数改一处，要先枚举它会波及的状态**。
