## 2. 逐项差距说明（本轮两处一手发现）

### 2.1 上一轮写的验收标准**按构造不可达** —— 这类「尺在奖励没做完的活」是新发现的一族（高）

**现象链**（每步本轮实跑）：

```
r96 报告 §4 下轮入口② :  「E2 棘轮降数：把 32 个套件逐个接进 browser_engine，
                          判据 …，**每接一个降 1**，接完可把基线归零」
                          验收标准 :  「BROWSER-ENGINE-PASS: 统一入口 N/32 已接（N 单调升）」
r96 的尺              :  未接入数 = 「AST 扫到裸 `chromium.launch(` 的件数」
r98 一手推演         :  接完一件 ⇒ 该件不再有裸 launch ⇒ **离开分母** ⇒ 分子恒 ≈0
⇒ 「N 单调升」按构造永不成立；而「未接入数」那条本身是正确的、也在用。
```

**为什么它此前 96 轮没人发现**：这条验收标准是**上一轮自己写的**，写的时候没有回头问
「这个数在我的尺下能不能涨」。它不是尺错，是**尺与验收标准不同族**。

**本轮修法**（`_test/browser_engine_declare_check.py`，见提交 `f57d91c`）：
取数面 子串 → **AST**；已接数改由「起点名册 `browser-engine-roster.json` − 现读」推导；
加 **E2b**（离开分母者必须「在册 ∧ import ∧ 裸 launch == 0」——封「删文件 / 改名 / 只 import 不删回退」
三种假降）、**E2c**（半接入残留 == 0）、**E2d**（解析失败件点名）；
`--census` 逐件对 defs，防本仓排障手册在册的「`Edit` 吞 `def` 行而 `py_compile`/`--selftest` 全过」。
本轮迁 **8** 件 ⇒ 余量 **24**，基线随之 32→24（只降不升）。selftest 15 → **37 条**。

### 2.2 「曲线只有一个点」—— 记了读数却从不问它相对上一轮变了什么（高，维度 4）

r96 跑出了 8/16/32/64 四档曲线，写下「8→64 路无塌方点」。**那条曲线当时只有一个点。**
于是「漂移」这个词在 r96 之后**无人量过**（`grep 漂移` 只命中报告散文，不在任何判据里）。

更要紧的是**地板管不住劣化**：`perf_baseline_check` 的地板是 `rps ≥ 50`、`p95 ≤ 400ms`。
rps 从 2368 掉到 900 仍然全在地板之上，判据一声不响。⇒「无塌方点」是对**这一轮**的形状陈述，
它不能被继承成「以后也无塌方点」。

**本轮修法**（`_test/perf_ramp_delta_check.py`，新增）：
只比**同一档位**的相邻两份台账、只对**劣化**判红（rps 跌 / p95 涨；改善不判红 ——
与「指标变好」无关的判红是噪声源，已写成设计腿钉住）。
三条硬要求各自对应一个此前踩过的坑：
- 档集不同 ⇒ 逐档 `NA(tier-missing)`，**不缩档、不补插、不取平均**（否则拿 8 比 16）；
- 「上一份」按**文件名日期**取，不按 mtime（`ledger_age` 实测踩过：同批台账 mtime 全是批量重写日）；
- 取不到两份 ⇒ rc=**2** UNVERIFIED，**不判绿也不判红**。

⚠️ **本件的诚实态**：目前只有一份 ramp 台账 ⇒ 主流程恒回 `UNVERIFIED`。
这不是坏态 —— 第二份由 `perf_baseline_check --ramp` 落盘时自动变成可比，
而在此之前**判据不假装有漂移结论**。

### 2.3 上一轮自己写下的「在受理面上没有读数」，本轮补掉（中，维度 3/7）

r97 追记里明写：「**A4 走 SKIP 还是 PASS 在受理面仍无读数**」——
「CI 绿」与「这一段验过」不是同一件事，而门面行只有裸 `VOICE-PASS`，两者在受理面上无法区分。
本轮（`0be8d93`）把档位**折进含判据词的那一行本身**，实测
`VOICE-PASS A4=PASS A5=PASS A6=PASS A7=PASS 真机腿=4/4 桩腿=3/3`（60 字符 ≤ 110 截断线）。

⚠️ 口径**收窄后**如实记：CI 覆盖**退出态**（A8/A9/A10 桩腿无 SKIP 分支），
**未覆盖真机麦克风路径**（A4/A5/A7 在 runner 上 SKIP）。两侧不是同一件事，**不得互相覆盖**。

### 2.4 peers 侧本轮**故意不重采**（方法论，与 r96 同款理由）

同轮 12 探针 burst 重采实测撞 GitHub secondary rate limit（r96 §2.4：`peer-hygiene` 12/17 行、
`peer-community` 5 行取数返回 403）。本轮只新增了**零网络**的判据，没有理由再叠一轮网络重采。
**代价如实说**：维度 1/3/7 的 peers 列与 r95 同源，本轮新增的 peers 读数为 **0**。
