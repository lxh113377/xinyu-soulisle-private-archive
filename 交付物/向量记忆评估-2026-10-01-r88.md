# 向量记忆评估（2026-10-01 / r88，P1 关闭项）

> r87 §3-#5「向量记忆侧车评估，未立项」的评估结论：**不立项**。理由与路径如下，触发条件命中时再重启。

## 1. 现状（磁盘现读）

- 记忆 = `chat_message` / `emotion_record` 两表（`MemoryService` + `MemoryController`，默认 H2 file，可切 MySQL 8）+ 73 条词表精确匹配。
- 缺失 = 语义召回（同义/模糊情绪表达跨会话关联）。对标：letta/SillyTavern 系 7/16 仓标配 RAG/向量检索。

## 2. 选项（可行性 1-2 句）

- **A. pgvector 侧车（Python 服务，Java 经 HTTP 调用）**：可行，符合 03-tech-stack 决策#1 重评口径「不用 Java 硬啃 AI 生态」；成本 = 新增一服务 + 部署目标翻倍 + 嵌入模型选型（本机无 GPU，本地嵌入慢）。
- **B. 维持两表 + 文档化扩展缝（零成本）**：可行，当前参赛场景（单用户演示会话）用精确记忆已够；扩展缝（`MemoryService` provider 化）在 `docs/EXTENSIONS.md` §4 已登记。

## 3. 结论

- 选 **B**：不引入向量库、不新增服务；本文件即评估交付物，P1-#5 关闭。
- 重启触发（任一）：多用户长期记忆需求 / 评委明确问语义召回 / 需要 RAG 答辩点。届时走 A 方案另立项。
