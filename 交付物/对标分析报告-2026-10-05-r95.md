## 2. 逐项差距说明

### 2.1 本轮最硬的一处：**CI 全绿契约装了 5 轮、一次都没真正生效过**（P0，r90 登记至今）

**现象链**（每一步都是本轮实跑，不是推断）：

```
$ git ls-files --error-unmatch -- .ci/contract.json      → rc≠0（从未入库）
$ greencheck.py run --repo-dir .
  [greencheck] UNKNOWN（契约未被 git 跟踪 ⇒ 拒绝执行（契约即代码；确认来源后再加 --allow-untrusted））
  rc=0                                        ← ⚠️ 注意这一行
$ cat .git/hooks/pre-push | grep -A2 'if "$PY"'
  if "$PY" "$GC" run --repo-dir "$ROOT"; then
      echo "[pre-push] PASS: 契约内 blocking 检查全绿，放行推送"
```

- `greencheck.py` 的硬规矩第 2 条明写「**契约必须被 git 跟踪**，否则 runner 拒绝执行」；
  它的 `main()` 对 `run` 模式走 `return 1 if res["verdict"] == "RED" else 0`
  ⇒ **UNKNOWN 落进 `else 0` ⇒ rc=0 ⇒ 钩子打印"PASS"并放行**。
- 钩子自己的头注写着「找不到判据时**失败关闭**并给修复命令」——
  **实测是恒放行**，且不抛异常、不打警告、不留痕。
- 前一版契约另有三个实测缺陷：`checks` 只 4 条且含 **2 组同名**（bootstrap 按 workflow
  *step 名*命名，一个 step 内跑多条命令就撞名）；CI 里最重的两条（`mvn verify` / 全量电池）
  **全被 defer**；`cost_ms` **全写死 5000（assumed）**，无一条实测。

**根因归属**：不是"忘了 `git add`"，而是**"有门"与"门有牙"分家**——与本仓已修过的
「判据印 FAIL 却无非零退出路径」是同一个根（r93 抓到 `j2_chat_contract`、r94 抓到
`j4_memory_check`，两次都是修例不修类 ⇒ 同族第三次复发）。r78 说过「有配置 ≠ 有门」，
这轮发现同一句话在本仓自己身上又成立了一次。

**修法与回执**：手写 blocking 14 条（本机 `Stopwatch` 逐条实测，合计 **10,021 ms** / 20s pre-push 预算），
name 唯一、每条带 `cost_source`、声明总预算 == 各条之和（可复算）、**每条 blocking 的脚本都在 CI 或电池里有执行位**；
deferred 6 条逐条写明承接面（哪条由 CI 哪个作业接、哪条因本机缺 JDK/Docker/node 而不拦）。
入库后实测：`[greencheck] GREEN`，14 条全绿，rc=0，10.1s。

**按 ★ 排会把"停更标杆"排到前面**。

**取数器的三个坑（本轮全部实测复现，与 A-project-better 补条七同族）**：
1. **分页 Link 正则失配 ⇒ 读数静默塌成常数**。GitHub 实测 Link 是
   `<…?page=1&per_page=1>; rel="prev", <…?page=877&per_page=1>; rel="last"`——
   第一版按字段序 / `split('>')[0]` 取页号，拿到 `1&per_page=1`，`int()` 抛错被 `except` 吞掉，
   **14/16 仓取数失败、异常既没进 unverified 计数也没影响分母**。正解：`page=(\d+)` 正则取全部再取 max。
2. **查询串 `+` 未编码 ⇒ 检索恒 0**。已进 `--selftest` 变异腿（`%2B` / `%3E%3D`）。
3. **必须双腿交叉验证**。分页法 vs `search/commits` 计数：16 仓 **15 仓逐字相等**，
   `MoodChat` 差 1（搜索索引滞后）⇒ 该格判 **unverified、不取平均、不择优**。

**self 侧按纪律 3 印明"不横比"**：本仓首个 commit = 2026-09-21，**历史跨度 13 天 < 30 天窗口**
⇒ 314 次/30 天无横比资格；只印率 10.47/日并注明窗口不满。

**三条可复用结论**：
1. **「站点宕机」与「本机浏览器打不开」是两件事**，必须先证站点。本轮三条腿（`curl` 200 /
   套件自身 HTTP 头实测全通 / msedge 单独探针 200）互证后，才敢把 3 条红判成环境面。
   若只看到 `ERR_CONNECTION_CLOSED` 就报"公网挂了"，会去查一个不存在的部署事故。
2. **4 条红里 3 条共用同一个根因**（负载下公网连接被关），说明这不是"5 个独立 flaky"，
   而是一个可指认的环境面。下轮若再复现，应优先查本机网络/代理，而不是逐条加有界重试。
3. **`voice` 的两种红必须分开记账**：不带 `BASE` 的失败是**用法错**（改端口默认值会掩盖电池接线），
   带 `BASE` 仍红才是判据红。本轮两者分别归因，避免把"我不会用"记成"门坏了"。

### 2.5 本轮两件新判据自检抓到的「本件自己的 bug」（可复用）

1. **`ci_contract_check.py`**：接线腿写成 `any(s in x for x in (ci_scripts, bat_scripts))` ——
   那是在两个 **set** 上迭代，做的是「`s` 是否是这两个 set 的成员」⇒ 恒 `False`
   ⇒ **14 条合法 blocking 全被误报「没人跑」**。正解：集合先摊平成名字集合再查。
   **只有正例腿抓得到这类「尺恒假」缺陷**（变异体腿抓的是「尺恒真」，方向相反）—— 两类腿缺一不可。
2. **`peer_maintenance_probe.py`**：`strftime("%Y-%m-%dT%00:%00:%SZ")` 抛
   `ValueError: Invalid format string`（`%00` 不是合法指令）；模块 docstring 未加 `r` 前缀致
   `\d` 触发 `SyntaxWarning`。教训：**Python 格式化串里 `%` 后必须是合法指令**，
   别照抄 shell 的 `%N` 补零写法。

### 2.6 真缺口的诚实定位：`vector_memory` 7/16，但**本轮仍判不立项**

`vector_memory` 是唯一"对手过半而我们没有"的能力格（7/16）。维持不立项的**理由要写清**，否则它
只是一句"以后再说"：

- **触发的是架构级决策，不是加个依赖**。`03-tech-stack.md` 决策 #1 的重评触发条件明写：
  「需要 Embedding / 向量检索 / RAG 记忆 → 届时按『**Python 侧服务 + Java HTTP 调用**』演进，
  **不要用 Java 硬啃 AI 生态**」。补这一格 = 引入第二个运行时。
- **产品侧收益不足以支撑**。心屿的召回机制是**情绪轨迹**（词典快判 → LLM 精判 → 分歧采信 LLM →
  危机优先），每轮对话的情绪上下文已经在请求里；向量召回解决的是"几百轮之后的语义检索"，
  与本产品的会话形态（一次倾诉一场）不匹配。
- **代价是明确的**：`03-tech-stack.md` 决策 #4 已登记"无多用户 / 无角色 / 无会话管理"，
  再叠一层向量库会把演示级单体推向需要运维的形态，与"零构建 + 单 jar 起服"的核心卖点冲突。

⇒ 结论：**这是有意的窄而深，不是遗漏**。触发条件：① 需要跨会话的语义召回；② 愿意接受双运行时。
