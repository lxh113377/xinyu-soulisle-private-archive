## 一、目标用户与典型场景

| 用户 | 场景 | 由场景推出的界面要求 |
|---|---|---|
| 高校学生 / 独居青年（主用户） | 夜里在手机上倾诉、情绪低落时随手打开 | 单手可达（控件 ≥44px）、输入不被系统放大、暗底久看不刺眼、正文不串行 |
| 首次到访者 | 从链接进来，不知道这页在讲什么 | 第一屏 3 秒说清是什么；一眼看到「往下滚」的下一步 |
| 评委 / 答辩现场 | 桌面大屏投屏、按幕讲解 | 能直接跳到某一幕；在线/离线状态一眼可辨；页面不因小动作崩 |
| 键盘 / 读屏 / 低视力用户 | 不用鼠标，或需要放大 | 焦点环可见、能跳过五幕直达对话、允许缩放、对比度达 AA |

据此确定的取舍：**不改成浅色亮调**（夜间使用刺眼），保留「深空 + 情绪色相」主视觉，浅色主题继续作为可选档维护。

## 二、优化范围与设计风格

- **设计风格**：现代极简 + 玻璃拟态，克制、低饱和；**沿用既有单一设计语言**，不引入第二套色板/图标体系。
- **覆盖组件**：

| 层 | 组件 | 改了什么 |
|---|---|---|
| 导航 | 顶栏 `#topbar`、幕次导航（新增）`#actnav`、跳转链接（新增）`.skip-link` | 滚动加深收紧；幕次直达 + 当前幕高亮；Tab 第一下直达输入框 |
| 内容 | 幕卡片 `.act-copy`、幕签 `.kicker`、标题 `h1/h2`、正文 `.lead`、承诺列表 `.promise` | 卡片顶部高光 + 统一圆角；幕签改胶囊；标题字距与断行均衡；正文提亮 + 行高 1.8 + 行宽 36em；项目符号配色 |
| 表单 | 输入框、下拉 `select`、复选框、设置弹窗 `dialog` | 聚焦双层环；弹窗位移入场 + 分隔线；操作区自成一块 |
| 列表 | 情绪芯片 `.emotion-chip`、对话日志 `.chat-log`、气泡 `.msg` | 芯片行高与底色；日志细滚动条 + 阻止滚动穿透；气泡内角收窄区分说话人、AI 侧浅阴影 |
| 弹窗 | `#dlg-settings` | 同上（入场**不用 scale**，避免撞 44px 触屏红线） |
| 按钮 | `.primary-btn`、`.ghost-btn` | 补齐按下/禁用态；时长与曲线统一走令牌 |
| 反馈 | 思考中气泡、焦点环、选区 | 呼吸动效；`::selection` 配色 |

## 三、逐项方案与预期效果

1. **令牌层收口**（`:root` 只增不改）：圆角 4 档、间距 4 档、时长 3 档 + 统一曲线、阴影 3 级、`--ink-2`/`--ring`/`--hi`。
   预期：全站不再各写各的 `.15s/.2s/.25s` 与 `10/12/14/18px` 圆角；新组件直接取令牌。
2. **顶栏滚动态**：滚过 8px 加 `.solid`（加深 + 收紧 4px）。预期：星雾亮起时顶栏文字始终压得住背景。
3. **幕次导航（新增）**：左侧竖排 5 点，当前幕青色高亮，hover/聚焦才展开文字标签。
   预期：五幕不再只能靠滚，评委可直接跳到第四幕看情绪曲线。
   位置是排除法的结果：竖向居中会被**全宽**的对话坞盖住（实测 hover 被 `.msg-text` 拦截）、贴右侧会撞表情面板
   `#face-hud`（实测被 `.face-hud-head` 拦截），最终取「顶栏下方左侧」，且 ≥900px 才显示。
4. **跳转链接（新增）**：Tab 第一下出现「跳到对话输入」。预期：键盘/读屏用户不必穿过五幕（A6 仍报焦点可见）。
5. **正文可读性**：`.lead` 15.5px/灰 → 16px/`--ink-2`/行高 1.8/行宽 36em。
   预期：中文一行约 30–36 字，长句回扫不易串行；`--ink-2` 在深底上对比度约 **10.9:1**（AA 阈值 4.5:1）。
6. **按钮三态 + 输入聚焦环**：hover / `:active`（轻微下压）/ `:disabled` 齐备；输入聚焦加 `--ring`。
   预期：手指点下去有回执，键盘与触屏都能确认「点到了哪」。
7. **气泡与日志**：气泡下方内侧角收窄 6px；AI 气泡带浅阴影；日志细滚动条 + `overscroll-behavior:contain`。
   预期：谁说的不看对齐也能分辨；滚动日志不再连带把整页滚走。
8. **弹窗**：位移 + 透明度入场；表单分组与操作区分隔线。预期：弹窗出现不突兀，「取消/保存」不易误点。
9. **响应式与设备适配**：
   - `(hover:none)` 下禁用 hover 变亮（触屏上 hover 会「粘」在最后点过的元素上）；
   - 矮屏（`max-height:560px`，横屏手机）让出叙事空间，坞限高 46vh；
   - ≤480px：对话输入行**换行**（输入框独占一行、四个按钮排第二行）；
   - `prefers-reduced-motion`：CSS 过渡与装饰动画整体收敛（GSAP 滚动叙事属内容驱动，不动）。
10. **缺陷修复 A（本轮实测发现，前后树都存在）**：390px 窄屏下输入框默认 `min-width:auto` 顶住 `flex:1`，
    `form.scrollWidth=438 > clientWidth=390`，**发送按钮被挤到 x=392（屏幕外）**，又被 `overflow-x:hidden` 整条裁掉
    ⇒ 手机端其实点不到「发送」。修法：`.chat-form input{flex:1 1 auto;min-width:0}` + ≤480 换行。
    实测：发送按钮 x **392 → 176**（屏内）、`scrollWidth` **438 → 390**（零溢出）。
    这条既有判据全部漏判：`mobile_check` 量的是控件尺寸与**页面级**横向溢出，而它是被 `overflow-x:hidden`
    裁掉的**坞内**溢出，两条判据都不覆盖。
11. **缺陷修复 B（非本轮引入，但会让整页打不开）**：`app.js` 的 `initFace` 在 `applyEnabled()` 里调 `setSwitch()`，
    而 `setSwitch` 来自 55 行之后 `initFaceHud()` 返回值的 `const` 解构 ⇒ TDZ 报错
    `Cannot access 'setSwitch' before initialization`。`initFace` 在顶层同步执行，**它一抛，后面的 boot、
    开场演示、对话接线全不执行**——表现是空白页，而不是「表情感知用不了」。
    修法：首次 `applyEnabled()` 下移到解构之后（原位留注释说明「为什么不能上移」）。
    证据：`_temp/base`（当前树 − 本轮 UI 改动）仍报同一错、`opening=null`；修复后 `opening=done`、零 pageerror。
12. **对话坞自动收起 + 点标题条展开（老大拍板补做）**：滚进幕内容即自动收起坞（只留 52px 标题条），
    点标题条展开；收起后标题条变指针热区。三条护栏（防误伤，缺一条都会被抱怨）：
    ① **焦点在坞内不收起**——正在打字/翻记录时一句话没打完坞就跑了，是最烦人的误伤；
    ② **只有向下挪够 80px 才收，向上滚不自动展开**（只收不放）——避免"来回抖两下坞就反复弹"；
    ③ **演示态（showtime）不动坞**（演示期坞本就整块让位给星雾）。
    键盘与读屏路径未受影响：展开/收起仍走带 `aria-expanded` 的 `#btn-dock`；
    刻意**不给** `#dock-bar` 加 `role=button`——它内部套着三个真按钮，再套一层会撞 axe 的嵌套交互规则。
    效果：第五幕/第四幕内容不再被坞压住（见 `after-08`），而"滚到哪一幕都能说"仍然成立（点一下即展开）。

    > **后续（r108，另一会话在途，非本轮）**：他们接着做了「坞与背景融合 + 全屏态」改造——
    > 收起条 52px→44px、标题条只留一个三态按钮（全屏/收起/展开）、`#btn-cam`/`#btn-lightshow`
    > 移进输入行、新增 `.full` 全屏态。我的滚动回调里被他们补了一条 `if (dockFull()) return;`
    > （全屏时页面滚动本就锁住，不该再把人从全屏踢出去），坞行为判据随之从 11 条扩到 13 条，
    > 含 r108 改造后复跑仍 **13/13 全绿**，两条路径（点标题条 / 点三态按钮）互不打架。
13. **界面残留的 Markdown 星号（既有已提交缺陷）**：第四幕披露语在界面上一字不差地显示成
    「**本演示实例的服务端**」——`data-rights.js` 里写的是 Markdown 强调标记，而那里是 `textContent`（纯文本）。
    已清掉星号（`REMOTE_TXT`/`LOCAL_TXT` 两处），保留原文措辞与关键字，`data_rights_check.py` 全绿。
