## 0. 三条口径先对齐（否则所有数字都会被读错）

|---|---|---|

## 2. 需求 1 · 情绪类别扩充：**8 个身份类 + 8 个细分子维度**

### 2.1 身份类（互斥，argmax 输出）

| 类 | 中文 | FACS 主证据 | 本轮是否动过 |
|---|---|---|---|
| joy | 愉悦 | AU12（颧大肌）+ AU6/AU7 眼周 | 否 |
| sadness | 低落 | AU1+AU4（眉内侧上抬） | 否 |
| anger | 烦躁 | AU4（压眉） | 否 |
| fear | 焦虑/恐惧 | AU5（上睑提升）+ AU20（横向拉唇） | **是**（直线修复，见 §3.1） |
| surprise | 惊讶 | AU1+AU2 + 竖直张口 | 否 |
| disgust | 厌恶 | AU9（鼻翼上提）+ AU10（上唇上提） | 否 |
| contempt | 轻蔑 | 单侧 AU12 + AU14（酒窝）不对称 | 否 |
| calm | 平静/**中性** | 残余量（其余都不高） | 否 |

关于**中性**：需求列的「中性」在本引擎中由 `calm` 承担（它就是"没有其它证据时的残余类"）。
**没有**把它拆成「中性 / 放松」两个身份类，原因写在 `face-smile-rules.js` subs 块注释里：
52 维 blendshape 不提供区分这两者的证据，拆出来就是**用数学模型伪造能力**。取而代之，
把它做成了可判定的子维度 `subs.neutral`（见 2.2），它是有证据的那种表述。

### 2.2 细分子维度（新增 8 条，与身份类**并存**而非互斥）

为什么走「并存标签」而不是「新增第 9/10 个身份类」：身份类互斥，一帧只能给一个答案；
而这些属性天然共存（"愉悦 + 真笑"、"低落 + 担忧"）。硬塞进 `emotions` 会逼引擎二选一，
而 Landmark 数据撑不起那个二选一。

| 维度 | 含义 | 证据来源 | 实测验证（典型输入） |
|---|---|---|---|
| `neutral` | 中性（帧里**没有任何**情绪证据） | 最强非平静分 < `weak.on` | 空向量 → true ✅ |
| `duchenne` | 真笑（AU6+AU12 眼周参与） | 眼周/口部比值 ≥ `smile.ratioOn` | 真笑向量 → true ✅ |
| `social` | 社交性微笑（只有口部） | 同上，比值不足 | 社交笑向量 → true ✅ |
| `masked` | 强颜欢笑（笑 + 紧张信号） | `smile.tensionOn` | — |
| `worry` | 担忧（区别于低落） | `browInnerUp ≥0.35` 且无口部向下 | worry 向量 → true，**sad 向量 → false** ✅ 判别成立 |
| `tense` | 紧绷/压抑（抿唇或压眉且不张口） | `subs.tense` 门槛 | tense 向量 → true ✅ |
| `micro` | 微表情（短时低幅：幅度 ≤0.30 且帧间跃变 ≥0.12） | 帧间欧氏距离 + 幅度门 | 需传 prev 帧，否则 `microAvailable=false` |
| `asymmetric` | 单侧不对称 | 左右嘴角不对称 ≥0.25 | contempt 向量 → true ✅ |

⚠️ **微表情的硬约束必须说清楚**：当前采样只有 **8fps（相邻样本间隔 125ms）**，而真微表情时长
40~200ms —— 一个微表情平均只会被采到 0~2 帧。所以 `micro` 现在只能给出**存在线索**，
给不出时长与类型。要真抓微表情必须把采样提到 ≥25fps（建议走独立快通道，别把整条推理链
开销抬高到 3 倍）。这条不是"待优化"，是**物理限制**，已按此登记，不会对外声称已支持。

## 3. 需求 2/3 · 准确率与混淆消解

### 3.1 本轮修复：fear 召回率长期 = 0

F13 一跑就把这个缺陷抓出来了：低强度 5 档 × fear，**fear 分恒低于 surprise**
（0.052 vs 0.090 … 0.194 vs 0.339），召回率 **0.00**。

根因（拆开算式，非猜测）：fear 的判据要求 ≥2 个区作证（`need:{fear:2}`），
而 fear 形态在低强度段只点亮 1 个区（嘴区 0.175，差 0.005 没过 `cue.min=0.18`）
⇒ 撞上 ×0.5 惩罚 ⇒ 0.389×0.5 = 0.194，永远压在 surprise 之下。
也就是说：当初为避免「常态被误报成恐惧」而加的这道闸，实际代价是**这一类根本不输出**。

| 方案 | fear 命中 | 全网格判错 |
|---|---|---|
| 原状 `need:{fear:2}` | **0/5** | 10/50 |
| `need:{}` | **5/5** | 5/50 |
| `need:{}` + fear 去除分母摊薄 | 5/5 | 5/50（与上同 ⇒ 摊薄不是根因） |

取**最小改动**（只改 need，不动权重）。附带收益：r166 台账里的遗留项
**C1（fear@0.12 笃定错报）当轮闭合**，笃定错报 1 → **0**。

## 4. 需求 4 · 实时性（真实被测，非估算）

`_test/face_latency_check.py`（F14）用**真脸 y4m 假摄像头**驱动 Chromium 走完整
VIDEO 模式整条链（取帧 → detectForVideo → read → EMA），与线上运行时同构。
两条 delegate 腿都量（`--delegate GPU|CPU`，默认 GPU）：**只报 GPU 等于只报好的一半**——
无独显或被浏览器拉黑的机器会自动回落 CPU，那条路径才决定体验下限。

| 腿 | 指标 | p50 | p95 | max |
|---|---|---|---|---|
| GPU（最好情况） | MediaPipe 推理 | 8.10 ms | 10.50 ms | 1843 ms（首帧预热） |
| GPU | 规则层 compute | 0.00 ms | 0.10 ms | 0.5 ms |
| GPU | **整链 e2e** | **8.30 ms** | **10.70 ms** | 1843 ms（首帧预热） |
| **CPU（最差情况）** | MediaPipe 推理 | 13.30 ms | 15.40 ms | 113.70 ms |
| CPU | **整链 e2e** | **13.30 ms** | **15.50 ms** | **114.20 ms** |

- 条件：每腿 n=120，**120/120 帧检出人脸**（不是"没脸时的空转"）；引擎 Edge 155.0.4283.45。
- **结论：两条腿的 p95 都远在预算内**（GPU 富余 9.3 倍、CPU 富余 6.5 倍）。
- ⚠️ **但 CPU 腿的单帧 max = 114.2ms 已越过 100ms**。所以这句话的准确说法是：
  「≤100ms 在 p95 口径成立，在"每一帧都不超"的口径**不成立**（CPU 最差情况偶发 114ms）」。
  若需求方理解的是后者，可行解只有两个：把采样从 8fps 降下来（单帧预算 125ms→250ms，
  牺牲交互跟手度），或确保走 GPU delegate（牺牲可覆盖设备面）——两者都是取舍，不是 bug。
- ⚠️ GPU 的 max 1843ms 是**首帧含模型预热**，稳态与之无关；F14 判 p95 而不是均值，就是这个原因。

## 5. 诚实结论表（哪些达标、哪些没有）

| 需求 | 目标 | 本轮结果 | 判定 |
|---|---|---|---|
| 1 类别扩充 ≥6 细分维度 | ≥6 | 身份 8 类 + 子维度 **8 条**（其中 6 条有实测验证） | ✅ 达标（但 UI 未接线，见下） |

| 1 微表情类细分 | 支持 | `micro` 维度可达但**受 8fps 物理限制**，仅给存在线索 | ⚠️ 部分达标 |
| 2 综合准确率 ≥90% | ≥90% | LOWINT 90.0% / **REAL 83.3%（有把握帧 100%）** | ❌ **未达标**（真实照片这一栏差 6.7 个点） |
| 2 跨光照/角度/年龄/性别 ≥90% | ≥90% | 轴已可测，但**样本 100% 落在「常光+正面」一桶**，暗光/过曝/侧脸 **n=0**；年龄/性别不可推导 | ❌ **不可宣称**（不是"没达标"，是"没考"） |
| 3 减少相似情绪混淆 | 降低 | fear 不再被 surprise 全量吃掉；`worry` 与 `sadness` 显式可判别 | ✅ 部分达标 |
| 4 单帧 ≤100ms | ≤100ms | **GPU p95 10.7ms / CPU p95 15.5ms**（每腿 120 帧全检出）；但 CPU 单帧 max **114.2ms 偶发超线** | ⚠️ p95 口径达标，"每帧必达"口径不达标 |
| 5 输出测试报告（逐类精确率/召回率 + 整体指标） | 有 | 本文件 + 机器件 `_test/face-prf-report-*.json` / `face-latency-*.json` | ✅ 达标 |

**一句话：三个✅、三个❌/⚠️。❌ 都不是"没做"，而是"证据不足够 support 那个断言"——
这里不打算用合成向量的 100% 去冒充真实人群的 90%。**
