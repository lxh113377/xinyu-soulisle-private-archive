## 1. 对比总览表

### 1a. 自家线上实测 ✅（`curl -D -` 逐路径，本地时刻 18:04 修前 / 18:40 修后）

| 路径 | 修前 CSP | 修前 Cache-Control | 修后 CSP | 修后 Cache-Control |
|---|---|---|---|---|
| `/` | **无** | `public, max-age=0, must-revalidate` | ✅ 11 条指令 | ✅ `no-cache` |
| `/index.html` | 无 | `no-cache`（但 **308 跳到 `/`**） | 随 `/` | 308 → 见 `/` |
| `/sw.js` | 无 | `no-cache` ✅ | ✅ | ✅ |
| `/js/app.js` | 无 | `public, max-age=0, must-revalidate` | ✅ | ✅ |

| `/api/chat` | 无 | —（Pages Function **不吃静态 `_headers`**） | ⚠️ 由函数自己回头，本轮单独取数 | 同左 |

**两条真实缺陷（不是"补个最佳实践"）**
1. **整站零 CSP**。唯一挡着严格 CSP 的东西是 r28 那段**内联 `<script>`**（全站就 1 个）——
   留着它就只能写 `script-src 'unsafe-inline'`，等于把 CSP 最有价值的指令作废。
2. **r28 的声明没落在生效路径上**：那版只给 `/index.html` 写 `no-cache`，而 Pages 会把
   `/index.html` **308 跳到 `/`** ⇒ 用户真正访问的入口拿的是 `public, max-age=0, must-revalidate`。
   功能上仍会回源校验（`must-revalidate` + `max-age=0`），**不是可用性缺陷**；
   但"我给入口 HTML 加了 no-cache"这句话在入口 URL 上**不成立** —— 而它已经这样写了 26 天。

## 2. 逐项差距说明（判据 `_test/headers_csp_check.py`，5 条阻断 + 1 条控制）

取数手法：**把同一份 `_headers` 在本地按 Cloudflare Pages 的路径语义回放**
（`/*` 通配 + 字面路径合并），再拿真实响应回来逐条对账 —— 然后在施加了 CSP 的那个服务器上
跑真页面。线上传输层只能测自己，本地回放能测**规则本身对不对**。

| # | 判据 | 修前 | 修后 ✅ |
|---|---|---|---|
| H5 | **拦截探针**：一段必须被 CSP 挡下的内联脚本，浏览器不拦就说明夹具没在施加 CSP | —— | 真拦下（violation 原文在册），**先判它**，否则 H1/H2 的绿色来自没生效的 CSP |
| H0 | 取数面非空（`_headers` 解析出 0 条规则时不得判绿） | —— | 有守卫（这条是 selftest 边界用例逼出来的，见 §4-3） |
| H1 | 声明 ⇄ 回放逐路径逐条等值 | 无 CSP 可测 | 5 个路径全部一致 |
| H2 | CSP 下应用可用（WebGL 活跃 / 五幕 / 对话链路 / 异常 0） | 不适用 | `五幕=5 对话=True 异常=0` |
| H3 | 严格性棘轮：script-src / style-src 禁 `'unsafe-inline'` `'unsafe-eval'` | 无 CSP | 无放宽（将来放宽必须改判据留名） |
| H4 | 前置不变量：`src/index.html` 内联 `<script>` 计数 = 0 | 1 个 | 0 个 |
| L1 | 线上入口 CSP 在位且无放宽 | `HEADSEC-UNVERIFIED`（见 §4-2） | ✅ 实测头 12 个、CSP 指令 11 条 |

**差距的本质**：不是"缺一个 CSP"，而是**这份文件 26 天来没有被任何一条判据按在线上测过**。
`_test/deploy_sync_check.py` 测 src⇄deploy 副本、`live_sync_check.py` 测内容字节，
唯独没人测"响应头是不是真回了"——于是 `/index.html` 那一条即使因 308 完全没作用在入口上，
也照样在文档里写着"已补两条"。

## 3. 顺手做与明确不做

**顺手做**
- `offline_shell_check` 的 A7 取数面从"只搜 index.html"扩成"页面 + 页面列出的 `js/*`"：
  注册语义一个字没变只是换了文件，**修的是判据取数面，不是回退产品改动**（R263）；
  反向能力保留（合成用例不列脚本时 A7 照样红，selftest 13/13 仍过）。
- 新模块补进 SW `PRECACHE` 清单 —— r45 就踩过"外提件没进预缓存致断网重载报错"，同族不再踩。
- 删掉 `/sw.js` 的第二份 CSP 变体：同一路径两处规则的合并顺序不可验证 ⇒ 属于"测不准的复杂度"。

**明确不做（写理由，不静默省略）**
| 项 | 处置 |
|---|---|
| `Permissions-Policy: microphone=()` | ⛔ **故意不写**。本站语音输入走 Web Speech ASR，要吃麦克风；写了会当场打断 `voice` 判据。缺省即允许，正是要的 |
| `/api/*` 的 CSP | ⛔ 不在本轮：Pages Function 不吃静态 `_headers`，要改的是函数自己回的头；已登记为 §6-2，且判据对它单独取数、取不到记 UNVERIFIED 不记 0 |
| 长期缓存 + immutable 的 vendor 策略 | ⏸ 沿用 r28 裁决（那是性能主张，不是离线壳前提；会让两端策略分叉） |
| 把 CSP 报给第三方扫描服务打分 | ⛔ 无授权外部面，属把用户数据送到第三方 |

   `headers_csp_check.py --live <prod URL>`，不可达时按 UNVERIFIED 出 rc=2 并**单独一行**（不得并入 PASS），
