## 2. 逐项差距说明（差距 → 归因 → 本轮处置 → 证据）

### 2.1 🔴 差距一：构建产物不带任何门禁（本轮主修，已闭合）

| 环节 | 内容 |
|---|---|
| 现象 | `server/src/test` 不存在；`pom.xml` 无 junit/surefire 声明 ⇒ `mvn package` 无论引擎对不对都成功 |
| 归因 | 我们的 51 条判据**全在仓库外面**（`_test/*.py`，要另起 jar、另开浏览器）。跨端对账很强，但它不构成"构建失败"这件事：一台不跑电池的机器（评委的机器、CI 的 `mvn package`）可以照样产出一个**情绪引擎已经静默退化**的 jar |
| 参照 | 9/16 家有 in-build 用例；连 ★1 的 Java 同栈 `MoodChat` 都有 Spring Initializr 脚手架 |
| 处置 | 补 4 个测试类 / 30 个用例 + `spring-boot-starter-test` + surefire `workingDirectory`；`mvn package` 从此自带这道门（CI java-build 那一步**本来就不带** `-DskipTests`，见 §2.3） |
| 证据 | `Tests run: 30, Failures: 0, Errors: 0` / `BUILD SUCCESS`（✅ 03:0x 本机 JDK17 + Maven 3.9.9 实跑）；复算 `mvn -B -f server/pom.xml test` |

**分工写死在测试类头部注释里，防止长成"同一判断两处实现"（M5⑥）**：
`_test/engine_consistency_check.py` 管 **JS 侧 == Java 侧**（跨端对账，需要两端都在）；
JUnit 管 **Java 侧自身的行为不变量**（危机短路、否定被程度副词覆盖、平分稳定序、两位小数、
次情绪 40% 门槛、空输入不炸、`harden()` 的同一性契约）—— 这些跨端对账**看不见**：两端一起错就一起绿。

### 2.2 🔴 差距二：in-build 门禁会在受理面上**静默消失**而无人盯（已封）

新增常驻判据 `_test/java_test_guard.py`（电池 54→**58** 中的一条，另含其自证桩）：

| 判据 | 盯什么 | 为什么单独列 |
|---|---|---|
| T1a/T1b | 测试文件数 ≥3、`@Test` 数 ≥24（实测 4 件 / 30 用例，余量 1 / 6） | 零用例不得判绿；下限**向下取整留余量**，加用例不会红、删用例会红 |
| T1c | 用例类不得"有 `@Test` 却零断言" | 空壳用例是最省力的凑数方式 |
| T2 | `pom` 声明 `spring-boot-starter-test` 且 `scope=test` | 依赖被顺手清掉 = 测试静默不编译 |
| T3 | surefire `workingDirectory` 指向 `${project.basedir}/..` | 词表 SSOT 按 `./src/` 解析；不指则**所有**加载词表的用例以"路径不存在"红（本轮实测踩到） |
| T4 | **CI `java-build` 的 mvn 构建步不得带 `-DskipTests`** | 带上了，受理面仍全绿，而构建期单测已经不存在 —— 这是本件存在的最大理由 |
| T5 | `server/src/main/java` 类数 > 0 | 扫错目录会让"0 用例"看起来完全正常 |

双向验 ✅：`--selftest` 10 类桩全过，其中**正例的夹具尺寸是算出来的**（首版 `3 件 × 7 用例 = 21 < 24`
被自己的判据判红，见 §7）；变异体三条各自翻红（零用例 / 缺依赖 / 带 skipTests）。

### 2.4 🟠 差距三：一条判据的红面**说不出自己为什么红**（本轮撞了三次，全修）

这是本轮真正的"教训密度最高"的一条，三处形态、同一族：

| 形态 | 现象（✅当次实测） | 真因 | 修法 |
|---|---|---|---|
| ① 等自己 | `online_check` 收口只剩 `CHAT_TAG: 逐字生成中…` | 用**固定 12s sleep** 等一条流式回复；上游慢一点就读到中间态 | 改**完成态轮询**：气泡数增加 + 正文非空 + 该气泡自身 tag 已落定（实测 2.9–3.7s 落定） |
| ② 折叠吞原因 | `VOICE-FAIL` 单行，原因在紧随其后的 `  - A4 …` 里 | 聚合器只挑**含判据词的行** ⇒ "标题带 FAIL、原因写在下面"这种形状恰好把最有用的行丢掉 | `fold_detail()` 带出命中行的 `-` 续行，并在 stdout 无 token 时补 stderr 末两行；抽成纯函数 + 5 类桩 + 3 个变异体全抓 |
| ③ 无分类的红 | 整跑三条红（`voice`/`online_check`/`public_check`）单跑全绿，收口看不出该查上游还是查代码 | 失败面缺"网络类 / 产品类"这一挡 —— 与 r35「非 1 即环境」少一挡给崩溃发通行证同族 | `online_check` 现按 `net::ERR_*`/5xx 分类打印；`voice`/`public_check` 同类改造登记为 P1（见 §6） |

①的两次自我推翻值得留档：第一版把气泡数基线取在**点击之后** ⇒ 三条各跑满 60s 假红；
第二版只数气泡 ⇒ 提交瞬间插入的空气泡 4ms 就"落定"，读到空 probe 又假红。
**"等"这件事的正确对象是被等者的完成态，不是等待者的时钟，也不是它出现过。**
