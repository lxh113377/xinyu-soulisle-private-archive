## 1. 功能完整性 — 评分 7/10（用户体验维度）

**优势**（引用真实内容）：
- 5幕叙事闭环完整：相遇→感知→陪伴→记忆→边界（index.html act1-act5），每幕有可交互实体（探针/对话/曲线），非纯展示。
- 降级链路真实存在：chat-agent.js `respond()` 中 `isOnline()` 判定 + try/catch 回落 `offlineReply`，实测无凭据时返回模板并标注"离线共情模板"，**不伪装在线**——这直接命中官方"系统稳定"判据。
- 危机转介独立于情绪评分：CRISIS 词表命中即最高优先级返回热线，emotion-engine.js:32 + chat-agent.js:26。

**短板**：
- 🔴 无语音输入（情感陪伴场景高频需求，Amica/数伴均已支持）
- 🟠 无多轮上下文记忆持久化（history 仅内存，刷新丢失）
- 🟠 情绪曲线只有单值折线，未按6情绪分色聚类展示

**优化方向**：P1 补 Web Speech API 语音输入；P2 情绪曲线分面显示。

## 2. 技术创新性 — 评分 8/15（创新性维度30分中）

**优势**：
- 情绪→可视化耦合是真融合：`setEmotion(color, intensity)` 让星雾颜色/透明度随情绪实时变化（three-scene.js:60），危机时红色脉冲（setCrisis）——**"情绪可被看见"是一句话能说清的差异点**，命中官方"AI与场景融合方式有突破"。
- 本地情绪引擎设计有技术含量：否定反转（NEG，权重-0.7）+ 程度修饰（DEG，太×1.4/有点×0.6）+ 多情绪加权排序，非简单关键词计数。

**短板（关键）**：
- 🔴 **创新性天花板受限于"情绪识别是本地词典"**：评委若追问"AI在哪"，词典方案深度不足。EmpaAva 前沿已是 LLM 编排的 Tri-Agent（感知→共情规划→具身渲染）。本项目有 chat-agent 的 LLM 共情链路，但**情绪识别环节未用模型**，是"AI+词典"混合而非"AI驱动"。
- 🟠 3D 是粒子星云，非角色形象（Amica用VRM数字人、数伴用晚晴角色）——陪伴感载体弱一档。

**优化方向**：见 03 号文档 P1-1——把情绪识别升级为"词典兜底 + LLM 精判"双路，架构图对齐。
