（一）产品概述与定位

1.1 背景与目标

中国科学院心理研究所发布的心理健康蓝皮书《中国国民心理健康发展报告（2021～2022）》显示，成年人群抑郁风险检出率为 10.6%、焦虑风险检出率为 15.8%；其中 18～24 岁年龄组的抑郁风险检出率达到 24.1%，显著高于其他年龄组。同系列《2020 年大学生心理健康现状与需求》调查显示，大学生中 18.5% 有抑郁倾向、4.2% 处于抑郁高风险；2025 年发布的《心理健康蓝皮书（2023—2024）》基于全国 79 家机构、逾 17 万份样本进一步确认了这一趋势。

这些数字说明：情绪困扰在大学生群体中是高频、常态、以非病理性为主的状态。大部分人需要的不是临床干预，而是一个随时可说话、说出来有人接住的日常出口。而现有"陪伴类"产品普遍存在三个结构性缺口：

缺口表现后果
只聊天通用聊天机器人不识别情绪，回复与情绪状态无关用户说"我很难过"，得到的仍是通用话术
不感知情绪不被结构化抽取，只隐含在上下文里系统无法基于情绪做策略选择，无法"对症"
看不见对话结束即结束，情绪没有被记录、没有趋势用户感受不到"被持续理解"，陪伴关系无法积累

本作品的目标：把"情绪"从聊天文本里抽出来，让它被识别（三路证据的情绪判定）、被呈现（3D 星雾随情绪变色）、被记住（情绪曲线），并在危机信号出现时被确定性兜底（规则短路 + 热线转介）——让陪伴产品真正做到"懂你"，而不是"回你"。

2.3 创新应用

创新点 1：三级共识路由——把"模型准不准"变成一个可切换、可实测的工程问题

业界常见做法是"接一个大模型完事"。本作品把情绪判定拆成危机短路 → 词典×模型共识 → LLM 可选仲裁三级，并用一个 route 开关把两种仲裁策略（词典裁决 / LLM 仲裁）做成可现场切换的对照实验。两种策略的取舍不是拍脑袋，而是被在线实测否决/证实过的（见 4.3 节：分歧升 LLM 使 73 条在线准确率从 98.6% 倒退至 94.5%，故上线策略采用词典裁决）。

创新点 2：危机安全边界永不概率化

自伤/轻生类表达命中危机词表时，系统跳过全部生成与判定逻辑，直接返回专业求助热线（全国心理援助热线 12356 等）。危机判定是确定性规则，绝不交给模型的随机性，也绝不在该路径上等待网络——盲测集 6 条危机改写句的实测结果反过来证明了这条规则的必要性（见 6.3 节）。

创新点 3：情绪驱动的 3D 可视化闭环

情绪标签与强度实时映射为 3D 星雾的颜色与粒子点亮数量（主情绪定主色，次情绪达主情绪分值 40% 才渲染第二种颜色，避免噪声词干扰画面），对话、可视化、记忆曲线三者共享同一条情绪数据流。

创新点 4：离线可用 + 诚实降级

浏览器应用壳（Service Worker）分级缓存：断网后五幕叙事与本地词典引擎对话完整可用；大模型不可用时切换离线共情模板并明示"离线"，绝不允许把模板伪装成在线 AI。对标实测：16 个同类开源项目中没有一家用浏览器应用壳做网页离线可用。

（三）功能设计与实现

3.1 核心功能的 AI 实现

3.1.1 三级情绪路由（感知层）

服务端引擎对每条输入并行产出词典读数与模型读数，路由规则如下（真实实现，非伪代码）：

public Outcome classify(String text) {
    EmotionEngine.ScanResult lex = EmotionEngine.scan(text);
    Verdict lexVerdict = new Verdict(lex.emotion(), lex.intensity());
    if (lex.crisis()) {                       // ⓪ 危机短路：确定性规则，不调用任何模型
        return new Outcome(lex, null, null, new Verdict("crisis", 1), "词典·危机拦截");
    }
    if (!"lexicon".equalsIgnoreCase(route) && model.enabled()) {
        ModelProxy.Verdict mv = model.classify(text);     // ① 本地微调模型腿
        if (mv != null) return routedFromModel(lex, mv, text);
    }
    return legacyRoute(text, lexVerdict);     // ② 模型腿不可用 → 词典+LLM 原双路
}

private Outcome routedFromModel(ScanResult lex, Verdict mv, String text) {
    if (mv.emotion().equals(lex.emotion())) { // 共识：双证据采信，模型置信度留证据链
        return new Outcome(lex, mv, null, new Verdict(lex.emotion(), lex.intensity()),
                String.format("词典+模型共识（conf=%.2f）", mv.confidence()));
    }
    // 分歧 → 词典裁决。在线实测（2026-10-09）：若分歧升 LLM，10 条分歧中 LLM 错 4 条，
    // 73 条在线准确率 98.6% → 94.5% 倒退，故 LLM 不持有判定权；
    // LLM 仲裁语义完整保留在 route=lexicon（旧双路），route 开关即两种策略的对照实验。
    return new Outcome(lex, mv, null, new Verdict(lex.emotion(), lex.intensity()),
            "词典与模型分歧 → 词典裁决");
}

该设计的结构性保证：共识与分歧两条路径的最终读数都锚定词典，因此路由层在词典主场评测集上的行为恒等于词典基线（2026-10-09 实测：离线/在线双口径均为 98.6%，72/73，miss 集合与词典基线逐条相同）——升级模型腿不会让既有准确率倒退。

3.1.2 共情对话生成（决策/生成层）

系统把识别到的情绪注入系统提示（例如"用户刚说的话被识别为主要情绪『低落』"），拼接近 10 轮上下文后调用大模型生成共情回复，限制字数与语气并要求结尾抛出开放式问题；回复以 SSE 逐字流式返回，上游不支持流式时自动回落整包并如实变更模式标签。

3.3 扩展性设计

  • 模型腿热插拔：模型服务地址经 model-url 配置注入，未配置时引擎行为与旧双路完全一致——模型腿是增强项而非依赖项；
  • route 开关：route=auto（共识+词典裁决）与 route=lexicon（词典+LLM 仲裁）两种策略可切换，天然支持答辩现场做策略对照演示；
  • 词表单一真相源：情绪词典被浏览器端引擎与 Java 服务端引擎共享，读取失败一律终止启动，绝不静默回退旧词表；一致性由守卫脚本三层比对（词表结构 / 逐条预测 / 汇总指标）；
  • 评测内建：GET /api/emotion/eval 随时复跑 73 条评测集并输出逐条结果与汇总指标，评委可现场验证。

4.2 代码实现

词典评分公式（可解释性来源）

词典层对每类情绪累加 权重 × 修正系数：取命中词前 3 字窗口，命中否定词则系数取 −0.7（否定词若被程度副词覆盖则不生效），再对窗口内命中的程度副词逐个相乘（如"非常"×1.5、"有点"×0.6）。仅总分 > 0 才计入候选，取最高分为主情绪；次情绪需达到主情绪分值的 40% 才参与渲染。

本地模型代理（ModelProxy，节选）

public Verdict classify(String text) {
    if (!enabled()) return null;                     // 未配置 → null，路由层自动走旧双路
    HttpRequest req = HttpRequest.newBuilder(URI.create(url + "/classify"))
            .timeout(Duration.ofMillis(timeoutMs))
            .header("Content-Type", "application/json")
            .POST(HttpRequest.BodyPublishers.ofString(payload, UTF_8)).build();
    HttpResponse<String> resp = http.send(req, BodyHandlers.ofString(UTF_8));
    if (resp.statusCode() != 200) { LOGGER.warn("non-200 status={}", resp.statusCode()); return null; }
    JsonNode j = mapper.readTree(resp.body());
    String emotion = j.path("emotion").asText("");
    if (!EmotionLexicon.EMOTIONS.contains(emotion)) return null;   // 非法标签一律拒绝
    double confidence = Math.max(0, Math.min(1, j.get("confidence").asDouble()));
    return new Verdict(emotion, intensity, confidence);            // 任何失败都显式回落并留日志
}

工程细节沉淀：回环调用必须显式 NO_PROXY（系统代理会转手本机请求）；JDK HttpClient 默认 HTTP/2 会发送 Upgrade: h2c 头导致 uvicorn 丢弃请求体（表现为 FastAPI 422），显式强制 HTTP/1.1 修复——两条都是实测踩坑后固化的修复。

被实测否决的两个设计（测试驱动的优化闭环）

否决实验 1：模型高置信主判
最初设想让微调模型在模型腿可用时直接做主判。实测：模型单腿在 73 条词典主场评测集上仅 86.6%（12 条 miss 集中在否定/程度对抗句，如"没什么好难过的"），切换主判会倒退。结论：回退为共识语义，把词典的可解释性与模型的语义鲁棒性以"双证据"方式组合。

否决实验 2：分歧升 LLM 仲裁 在线实测把 10 条词典×模型分歧升给 LLM 仲裁后，73 条在线准确率从 98.6% 倒退至 94.5%（LLM 错 4 条）。结论：上线策略改为词典裁决，LLM 仲裁保留为 route=lexicon 可切换语义——这个开关本身就是两种策略的对照实验，可在答辩现场演示。

5.2 市场分析

AI 陪伴赛道用户增长迅速但同质化严重：多数产品把大模型直接接进聊天框，情绪不可感知、不可验证、不可视。本作品的竞争力集中在三点：可验证的判定证据链（评测集现场复跑 + 逐条判定路径展示）、本地模型腿带来的零边际成本与离线可用（LLM 调用次数在共识语义下降为 0）、规则化的危机安全边界（校园场景的合规刚需）。这三点是当前同类产品普遍不具备、且评委可当场验证的差异点。

5.3 成果总结

  • 情绪判定：三级共识路由上线；自建 73 条评测集准确率 98.6%（危机召回 6/6，双口径恒等）；自研微调模型在 237 条冻结盲测集上准确率 92.2%、单条 26.6 ms；
  • 工程质量：101 个 JUnit 用例全绿，覆盖率 LINE 97.00% / BRANCH 95.21%（门禁化）；前后端契约 1:1 对账；三路部署全部在线可用；
  • 安全与诚信：危机拦截规则化且永不概率化；离线降级诚实标注，绝不以模板冒充在线 AI。

5.4 未来规划（不足与改进）

我们如实列出当前短板与对应的改进路线：

当前不足（如实声明）改进方向
域偏移：上线策略以词典读数为准，而盲测显示词典在口语化生成域仅 46.3%（模型 92.2%）——词典裁决保证了"不倒退"，但也意味着域外口语表达可能被判平/误判（如"撑不住了"被判 calm）把固定"词典裁决"升级为按域自适应加权：词典无情绪词命中且模型高置信时采信模型，同时保留 73 条评测集作为回归硬门，扩评测集覆盖口语域
危机词表盲区：盲测 6 条危机改写句仅命中 2 条（"想消失""撑不下去"类改写未覆盖）扩充危机词表并引入改写样本回归（安全层改进，不涉及模型，优先级最高）
尚未开展真实用户试点以免费在线版积累真实使用与反馈，再与高校心理中心接洽数据合规审查后的试点
