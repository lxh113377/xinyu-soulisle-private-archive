# 教程 01 · 离线演示（不联网、不配密钥，也能把全链路走一遍）

> 这一章解决的是一句话就能问倒人的问题：**"没有 Key、没有网，这个作品还能演吗？"**
> 答案是能，而且界面会**明示**它处在离线态，不会伪装在线（这是红线，不是客气）。
> 快速起步看 [`QUICKSTART.md`](QUICKSTART.md)；这一章讲"为什么这样设计"和"怎么自己验证"。

## 1. 三条降级路，各自降级的是什么

| 降级点 | 触发条件 | 界面表现 | 代码位置 |
|---|---|---|---|
| WebGL 星雾 | 无 WebGL2 或被禁用 | 星雾退化为 CSS 渐变背景，叙事与对话不受影响 | `src/js/three-scene.js`（渲染入口探测）＋ `src/css/style.css` 渐变兜底 |
| 在线 LLM | 上游不可达 / 无 Key / 代理不可用 | 回复走本地模板，并在对话坞明示当前模式 | `src/js/chat-agent.js`（在线⇄离线切换）＋ `src/js/demo-config.js` |
| 服务端记忆 | `cfg.remote !== true` 或本会话已确认 `/api/memory` 不可用 | 退回浏览器 `localStorage`，星图照常点亮 | `src/js/memory-store.js`（`isRemote()` 与熔断位 `remoteDown`） |

关键设计：**降级不是"功能消失"，是"换一条能跑的路 + 把当前路标出来"**。
所以演示时一旦被问到"这断网了怎么办"，答案是当场断给她看，而不是解释。

## 2. 最小离线演示（三步，全程零密钥）

```bash
# ① 起一个静态服务（不需要 Java、不需要 Maven）
python -m http.server 8123 --directory src

# ② 浏览器打开 http://127.0.0.1:8123/ ，按 QUICKSTART 的十分钟自证清单走
# ③ 想看"离线态长什么样"：把 demo-config 里的代理指向一个不存在的端口再看一次
```

> 为什么第 ③ 步能当演示用：`_test/browser_check.py` 正是用"不可达端点"做**单变量对照**的——
> 它先跑一次能通的（在线腿），再跑一次注定不通的（离线腿），两次只差那一个端点。
> 只有"对照组也失败"才能证明失败来自被测条件，而不是脚本自己写错了地址。
> （这一手是 J1 当天抓到的：当时误把脚本自注入的 `127.0.0.1:18123` 当成 Java 服务端的错，
>  换回旧 `http.server` 同样报 `ERR_CONNECTION_REFUSED` 才看清是脚本自己的降级腿。）

## 3. 自己验证（不用信我这段话）

```bash
python _test/browser_check.py            # 离线降级链路 + 回滚可见性 + 双色 + 滚动淡入淡出
python _test/pixel_dual_check.py         # 双色星雾在**屏幕像素上**可分辨（带单色对照）
python _test/lightshow_check.py          # 一键点亮是"清屏 + 播放过程"（黑屏关键帧有效像素=0 才算成立）
```

三条都是常驻回归，改动 `src/` 后必须复跑；它们都不需要联网。

## 4. 常见的三个"看起来坏了"

- **星雾不动**：先看是不是 WebGL 降级（降级时是渐变，本来就不动）。判据：`browser_check.py` 的 `typeof THREE` 断言。
- **回复很机械**：那是离线模板，界面应当明示模式。若界面**没**明示，那才是缺陷，按 bug 报。
- **清屏按钮点没反应**：已知遮挡缺陷（`#btn-clear` 被 `#dock-bar` 吃掉点击，已归因在册）。
  存在性 ≠ 可达性——新增浮层/按钮都要**真点一次**，样式判据看不见遮挡。

## 5. 这一章为什么叫 `tutorial-01-*`

文档维的尺子（`_test/peer_docs_probe.py`）对"教程"这一位**按文件名判**，
命中 `quickstart|tutorial|how-to|guide|handbook` 才算。
`docs/README.md` 里的章节名不算——那不是口径漏洞，是**peers 也按同一把尺量**的代价：
自研项目把入门只写在 README 里时，它的教程位照样是 0。命名即口径。
