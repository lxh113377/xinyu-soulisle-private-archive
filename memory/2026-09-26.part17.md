## 二、共享 index 的来回两次（今天真实发生，两个方向都中了）

1. **我把他人的裹进来**：`git add -- 我的文件` 后 commit，回执里多出 1 行 `A-project-better/SKILL.md`
   —— 那是并行会话**早已 staged** 的文件（共享 index）。我当时按 numstat 检查的是"暂存了什么"，
   没检查"index 里原本躺着什么"。
2. **他人把我的带走**：我 `reset --soft` 撤掉后用 `git commit --only -m … -- <path>` 重做，
   结果消息参数写在 `--` 之后被当成 pathspec（`did not match any file(s)`）⇒ 提交失败；
   就在这几秒里，并行会话的一笔 `rule_editor` 提交把**我已 staged 的 consulting-analysis/SKILL.md 一起带走并推上远端**
   （`origin/main` 上我的 ⑫ 内容挂在他的 commit message 下）。

⇒ 三条硬口径（已写进 cps 1.5.0 卷11 §4，这里留一手证据）：
- **commit 之前**先看 `git status --porcelain` 的**第一列**（index 态），而不是只看自己 add 了什么；
- `git commit --only -m "…" -- <path>`：**消息参数必须在 `--` 之前**（`--` 之后全是 pathspec）；
- 在共享仓库里，"改完立刻提交"比"改完先去干别的"安全——**窗口越短，被他人带走的概率越低**。
