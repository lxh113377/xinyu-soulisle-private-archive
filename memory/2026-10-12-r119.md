## 一手坑（必须留，否则会复发）

1. **本仓用编辑工具改 `.py` 会写出 CRLF**，被 `eol_parity_check` 判红（`dock_auto_check.py` 落 168 个 CR）。
   正解：`Path.read_bytes()` → `replace(b"\r\n", b"\n")` → `write_bytes()` 整体回写，再复跑该判据确认自己从红名单消失。
   本轮所有新写/改写的件一律按字节 LF 落盘（`dump_bytes` 同口径）。
2. **判据的门面行不许把「取不到」印成「没有」**：`docs/openapi.yaml` 与 Java 端点是 11 ⇄ 11（本轮实测），
   上一类报告常写的「API 文档缺失」在这一格**不成立**；同时 peers 缺 bench 数记 NA-DECLARED 而不是 0。
3. **正向桩要先自证基线**：`--selftest` 首版的"齐 8 维"桩因为另几维是空格而红 ⇒ 桩在测自己的构造而不是测 audit；
   改成 `mk_dims()` 先造满格基线再定点破坏，并加一条「基线本身必须不红」的守卫腿。
4. **自己新造的尺要回手查重复**：改造二把 `bench_rollup` 已算过的量又算一遍（同一事实两把尺），
   当场在收口前拆掉——去重的判据自己最容易造出第二把尺。
