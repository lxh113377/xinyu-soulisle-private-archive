## r102 · 面部表情识别精度与种类（2026-10-10）

4. **`family` 映射 + `confidence` + 界面接线**：表情侧 8 类对齐文本 6 类（供分歧标注）；
   margin 低时 `confident=false`，界面显示「读数不稳」。

### 关键决策：表情侧 8 类 ≠ 文本侧 6 类（勿"顺手对齐"）

`emotion-lexicon.js` 是 **JS/Java 双端 SSOT**，给它加类要连带改 Java 侧 + 评测集 + 守卫。
而表情类别上限由 **blendshape 决定，不由词表决定** ⇒ 表情侧在 `face-smile-rules.js`
**自持 8 类**（含自持 `labels`/`colors`），语义关系写在 `family` 里，**不碰双端 SSOT**。

### 两条返工教训（都是判据抓出来的，不是我看出来的）

- **E1**：F11 首版报 8 条「强度非单调」—— **是判据自己量错了对象**（拿"当前主情绪"的
  强度去判"某个类的分数"单调性；而向量压弱后 argmax 会合法退回 calm）。改为查该类自己的分数。
- **E2**：强颜欢笑被判 calm —— **代码默认值与它自己注释不一致**（注释说 `need` 默认 1，
  代码写的是 `R.cue.need`=2 ⇒ joy 也被要求两区，而社交性微笑按定义就是只有口部参与）。
  ⇒ **注释写了不等于代码是那样**；只有拿真实向量跑才看得见（真笑恰好满足两区要求，掩盖了它）。

### 一个更贵的教训：别拿高强度向量验低强度缺陷

中途我用「用力压眉 0.95」测多线索佐证规则，两种配置输出一致 ⇒ 判定它是死代码并删掉。
删完 F11 立刻红：「压眉 0.4」这档**轻皱**又变回 anger 假阳性。
**假阳性恰恰发生在低强度那档**（专注时人不会用力压眉），而高强度样本恰好是"看起来正常"的那个。
⇒ 凡是「我以为它在起作用」的规则，都要专门造一条「它不起作用」的向量去证伪它。
