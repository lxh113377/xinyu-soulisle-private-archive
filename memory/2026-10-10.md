## r87d 补丁（老大第三轮反馈：授权过却打不开、不弹窗、"只有开/关选项"）

- **问题**：`#btn-cam` 是**应用级总闸**，但文案（"摄像头"）让用户以为它是权限开关；
  而真出事时（浏览器记住了阻止 / Windows 相机隐私关着 / 设备被占用 / 驱动异常 / 根本没有设备）
  界面一律只报"暂不可用"——**分不清是哪一层的病**，用户无从处置。
- **修法（分层自检 + 分类处方）**：
  ① 引擎加 `diagnose()`：`permissions.query({name:'camera'})` 权限状态 +
  `enumerateDevices()` 摄像头设备数/名称，结果挂 `window.__XINYU_FACE_DIAG__`；
  ② 开局就自检并把结论写进状态行（被阻止 → "锁形图标→摄像头→允许"；已授权 → 报设备数；无设备 → 报驱动）；
  ③ 出错时在错误文案后附自检读数（权限=X，设备=N 个）；
  ④ `getUserMedia` 加 **12s 超时**：系统级拦截（Windows 隐私开关/杀软/驱动异常）时这个 promise
  会一直挂着不 resolve，界面就永远停在"等待授权…"——现在会自报家门；
  ⑤ 错误文案按类型分开：NotAllowedError / NotReadableError / TrackStartError / AbortError /
  NotFoundError / gum-timeout / no-video-device，每类给**可执行**的处置步骤；
  ⑥ 开关 title 写明"心屿是否使用摄像头；浏览器/系统授权仍由你自己控制"。
- **判据**：F8（enumerateDevices 返回空 ⇒ 入口隐藏 + reason=no-video-device + 状态行提"设备"）、
  F9（getUserMedia 抛 NotAllowedError ⇒ 状态行必须含"锁形图标"指引）。两条都打印实测文案作证据。
  预算：app.js →30,901、face-engine.js →18,467（增量=分层自检与五类处方）。

## r87c 补丁（老大第二轮反馈：反复点摄像头，一直"正在识别"且**不弹授权窗**）

- **根因（代码里找到的，不是环境）**：旧版 `start()` 的 await 顺序是
  `whenReady(模型 13MB) → getUserMedia`，也就是**先下模型再要权限** ⇒ 点下去十几秒内浏览器
  不弹授权窗；Safari 更硬（getUserMedia 需要 user gesture，跨过 await 后 gesture 过期 ⇒ 永不弹）。
  反复点击则只是不断重排模型加载 ⇒ 用户看到"没反应/一直正在识别"。
- **修法**：授权提到**第一个 await**（点下去立刻弹窗）→ 拿流 → 再加载模型。
  配套三件：① 引擎加 `phase`（permission/model/warmup/running）并进 `stats()`；
  ② 对话坞新增 `#face-status` 状态行（用户点的地方可见），HUD 标签按 phase 分阶段说人话；
  ③ 启动中再点 = **取消**（不再用 disabled 吞掉点击——弹窗晾着时按钮必须还能点）。
- **错误文案**：`NotAllowedError` → "浏览器已阻止摄像头：点地址栏左侧锁形图标 → 摄像头 → 允许，
  再点一次开启"（被记住的阻止不会有弹窗，只能这样引导）；`getUserMedia-failed` 补占用/系统隐私设置提示。
- **判据**：F7「授权必须早于模型加载」——把 getUserMedia 拖慢 800ms 并记录调用时刻 +
  记录首个 mediapipe 资源请求时刻，实测 `gum@178 < mediapipe_fetch@1111`，阶段 `permission→model→running`。
- 预算：app.js →29,155（增量=看门狗 + 总闸 + 状态行 + 取消语义，全是真代码）。

## r87b 补丁（老大公网实测反馈：小窗永远"正在识别…"）

- **根因**：开摄像头但画面里没人时，没有任何一帧读数回来，HUD 标签就停在初始态"正在识别…"——
  状态没翻面，用户以为坏了。修法：HUD 看门狗按 `FaceEngine.stats()` 的读数新旧翻面
  （3s 没出过读数 → "没有看到人脸——请正对摄像头"；出过读数但 2.5s 没更新 → "人脸离开了"）。
- **摄像头总闸 `#btn-cam`**（老大点名要的开关）：对话坞工具条上，关 = 立即真停在跑的流 +
  隐藏全部摄像头入口 + `localStorage peiliao.face.cam.v1=off` 记住选择；开 = 恢复入口
  （能否真用仍由能力探测说了算）。引擎侧 `FaceEngine.enabled/setEnabled` 双保险，
  `start()` 对 `cam-disabled` 也拒开。开关按钮**永远可见**（没有摄像头的设备也该有总闸）。
- 判据：F4 增"关总闸 → 入口消失/流真停/记住；再开 → 入口恢复"腿；预算 app.js →27,652、
  face-engine.js →15,426（增量是真代码：看门狗 + 开关）。公网复验 PASS。

## 本轮的实测结论（都是踩出来的，不是抄的）

- **CSP `'unsafe-eval'` 被迫保留**：MediaPipe wasm 链要 eval；只给 `'wasm-unsafe-eval'` 时
  公网报 `Evaluating a string as JavaScript violates …` 且推理器永远建不起来。
  本地（无 CSP）测不出来 ⇒ 又一条"本地绿 ≠ 线上成立"。已按项目规矩立具名豁免
  `CSP-EVAL-EXCEPTION`（`headers_csp_check` H3/L2 认标记，selftest 13→15 腿）。
- **`videoEl.play()` 的 promise 可能永不 settle**（公网实测吊死开启链 60s+）⇒ 改"发起即走 + 1.5s 兜底"。
- **启动未完成时点关闭，摄像头会留在开着的状态**（隐私竞态）⇒ FaceEngine 加会话令牌，
  stop 作废在途 start；公网验收腿现在会专门抓这一条。
- **初版模型是 eager 加载**（模块一执行就下 13MB）⇒ 改 `ensure()` 惰性，点开才下。
- **`.mjs` MIME 不统一**：本机 http.server 发 `text/plain` ⇒ 浏览器拒绝执行模块脚本 ⇒
  vendor 改名 `vision_bundle.js`（字节不变）。
- **Duchenne 门槛被真照片证伪**：首版 `ratioOn=0.45` 把 4 张真笑照全判成"社交笑"
  （实测 ratio 0.269–0.326）⇒ 重标 0.20 并把标定数据写进 rules 注释；F5 加"真笑照必须判 duchenne"腿。
- **SW PRECACHE 数组注释禁出现双引号/数组结束符字面量**（判据按源码正则复算清单）——本轮连踩两次。
- **入场动画不能用 scale**：`getBoundingClientRect` 会把缩放算进尺寸，动画期按钮实测 43px，
  撞 44px 触屏红线 ⇒ 只用位移+透明度。
