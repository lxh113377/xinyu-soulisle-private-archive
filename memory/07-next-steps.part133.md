### 🔴 本轮最重要的发现：anger 的「漏报 vs 误报」是**无解取舍**，不是阈值没调好

真愤怒照（face-api.js）在 blendshape 上的实测 AU 分布是
**browDown 0.64/0.59 而其余全 0**（无鼻翼、无抿唇、无张口、无眼睁大）。
而 r102 的 `need:{anger:2}`（当初为压"专注轻皱被判愤怒"而设）要求「眉区之外再来一区」
—— 代价就是**真愤怒也判不出来**。

| 样本 | 结构 | 现状（need:2） | 方案 A（去掉 need:2） |
|---|---|---|---|
| 真愤怒 browDown 0.64 | 仅眉区 | ✗ calm | ✓ anger |
| 专注轻皱 browDown 0.40 | 仅眉区 | ✓ calm | ✗ anger |
| 说话+微皱 browDown 0.30 | 仅眉区 | ✓ calm | ✗ anger |

**两者在 blendshape 空间里结构完全相同，只有幅度之差** ⇒ 任何阈值都在
「漏掉真愤怒」与「误报专注」之间二选一，**没有第三个正解**。
连 r102 新加的 `confidence` 也分不开（实测两者 margin 0.530 / 0.345，都判"确定"）。

**⇒ 需要人来定，两个方向**：
- **方向甲（保专注）**：维持现状。anger 在表情侧**不可达**，改为在文档/界面如实声明
  "表情分不出愤怒，愤怒只由文字判定"。
- **方向乙（保真怒）**：去掉 `need:{anger:2}`。真愤怒能判出来，代价是专注时会闪红。
  考虑到本作品定位是情绪陪伴、且用户表达愤怒是**核心需求**，
  而"专注被读成愤怒"是**几秒内自愈**的瞬时噪声 —— 倾向乙，但这是产品取舍不是技术取舍。

### Commons 那条路已实测证伪（不要再试第二遍）

| 尝试 | 实测结果 |
|---|---|
| `generator=search` 全文检索 5 类 | 13–56 候选/类，可用真实人脸**近乎为零**（画作/版画/书籍插页/猫/考拉/月亮） |
| 改走 `categorymembers` 分类树（`Category:Human sadness` 等） | 161 张候选 → 目检后**多数是纪念照/氛围照**，人脸非当下表情；喂真模型后 **12 张里 3 张检不出人脸、6 张判 calm** |
| 逐张目检 | 发现**损坏图**（#000、#029 是明显的渲染错误图，文件名却是正常的 sadness 题材）⇒ 再次证明目检不可省 |
| 提高分辨率（480px → 原图 8.6MB） | **不是分辨率问题**：同一张愤怒照两种尺寸 AU 都是 ≈0 |
| 改用 face-api.js `test/images`（带标注、MIT） | **可用**：4/4 检出，surprise 2/2 判对 |

**结论**：公开域**情绪类**照片几乎都是「氛围/纪念」而非「表情瞬间」；
可用的是**表情识别项目自带的标注测试图**（face-api.js / fer / MediaPipe samples 仓库）。
后续扩类应直接去这些仓库找，别再走 Commons 分类树。

**仍缺**：sadness / fear / disgust / contempt 四类的真实标注照片（face-api.js 只有
angry/surprised 两张），以及**「专注/中性」这一类**的标注样本 ——
没有后者，anger 的取舍就只能靠上面的定性论证。
