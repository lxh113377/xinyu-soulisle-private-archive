## 三项回执

### ① BLIND-RED 未兜底裸点 21 → 0

逐个包 try 要动 8 个文件几十处 ⇒ 改走**进程级兜底**：`check_instrument.install_excepthook(name)`。
2 行覆盖整份脚本，且兜住**所有**未捕获异常（不止 assert / wait 两类）。

先做了可行性验证（这一步不能省）：excepthook 里 `sys.exit(code)` 到底能不能决定退出码 ——
实测三种异常（assert / timeout / 其他）**都拿到 rc=2**，且不打 "Error in sys.excepthook" 噪音。

| 语义 | 结论行 | rc |
|---|---|---|
| AssertionError | `NAME-RED 断言未通过：<msg>` | 1 |
| TimeoutError / *Timeout | `NAME-UNVERIFIED 判据未跑完（超时）：<msg>` | 2 |
| 其他异常 | `NAME-RED 仪器异常（判据未出结论）：<type>: <msg>` | 1 |

棘轮同步升级为「**未兜底**裸点」：装了 `install_excepthook` 或整段在 try 内的裸点**不判红**
（判据管的是结论行有没有，不是 assert 写没写）。自检加第三向变异验证这条区分。
`PASS 未兜底裸点=0 ≤ 基线 0（已兜底 21 处｜在册 95 件）`；`--selftest` 三向变异成立。
`settle_wait.py` 是公共件 ⇒ 只在 `if __name__` 里装，避免污染 import 它的调用方（实测 selftest 13/13 不受影响）。

## 一手发现（三条，都会再犯）

1. **词表 JSON 体内禁止写注释**。`emotion-lexicon.js` 自称"纯 JSON 字面量"，
   Java 用 Jackson 解析 ⇒ `//` 当场炸在 `Unexpected character ('/')`。
   我把说明写进 JSON 体内就踩了；说明一律放文件头块注释（已把这条警告写进文件头）。
2. **改判据必须同步改它的自检**。本轮两次撞上：E2 分母语义变了但自检还断言旧语义（44/45 红）、
   棘轮口径变了但自检只有两向变异。自检是判据的一部分，不是附属品。
3. **终点态会让判据自己判自己「不可验」**。E2 余量归零后原逻辑固定 UNVERIFIED ——
   任何"分母为 0 ⇒ 未验"的设计，在目标达成那天都会把成功读成故障。
