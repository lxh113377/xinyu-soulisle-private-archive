## 二、这一跑顺手量到的新事实：同环境跨 run 也不稳

| 采样 | 环境 | p95 峰值 | 吞吐 |
|---|---|---|---|
| 本机 `--reps 25` @21:2x | Windows warm JVM | 26.2ms | 2026.9 rps |
| CI run `36245610695` @21:39 | Linux 共享 runner | 3.3ms | 1178.6 rps |
| CI run `36247073027` @22:06 | 同上（同代码） | **3.7ms** | **1035.7 rps** |

⇒ 同一判据、同一环境、同一代码，两次 CI 吞吐差 **12%**（1178.6 → 1035.7）。
所以「禁引用绝对值」不只针对跨环境，**跨 run 同样成立**。
这正是阈值必须按数量级余量钉的理由：吞吐地板 50 rps vs 实测 ~1000（~20×）、
p95 预算 400ms vs 实测个位数（~100×）。**贴着实测值钉阈值的那类判据，在这种 runner 上会自判红。**
