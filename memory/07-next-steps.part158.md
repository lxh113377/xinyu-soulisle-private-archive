## 一手教训（本轮两次同族误判，同一条根）

**「grep 一个函数名命中在哪」推不出「它有没有被调用」，也推不出「它有没有被测过」。**

1. 误判一：判 ``verifyCitations``「未实现」，依据是 grep 两行命中都在注释里 —— 实际 ``chat-agent.js:196-214``
   有完整实现，真缺口是**零调用点**。若按原判去实现，会造出与既有契约不同（剥离 vs 标注）的第二份实现。
2. 误判二：造完重复件才发现 ``kb_citation_check.py``（**已在电池、C1-C7 全过**）已覆盖全部三结局。

⇒ 纪律：对「这个能力是否已存在」下结论前**必须同验三面：定义处 / 调用处 / 判据处**，
且**先查电池 SUITES 与 ``docs/quality-gates.md``**（G16 四面对账本就是这条的机器面，本轮它亲自抓出了我的孤儿件）。

另一条同族：``quote_wiring_r133_check.py --selftest`` 的自证最初用文本模式写回产品文件，
Windows 把 ``\n`` 翻成 ``\r\n`` ⇒ 还原校验逐字节对不上（判红但不是它该抓的缺陷）。
**改产品文件的自证脚本一律走二进制读写**。
