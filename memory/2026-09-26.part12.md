## 一、性能维拆成两问分别取证

**问 1：能不能横向比？** 16 仓 × 文件树 + README 双通道找性能工程件。
**原始计数不能用**，我自己造的匹配器有两类假阳性：`bench` 命中 `workbench`（28 条）、
`Performance` 命中 NuGet 带入的 `System.Diagnostics.Performance*.dll`（7 条）。
语境归因后：只有 sapphire `tools/tts_benchmark.py` 一家是明确压测件，且**无一家公开可比数值**
⇒ 这一维**不可横向比较**，报告里任何「比某仓快 N%」都不允许产生（已写成 06 红线）。

**问 2：自己到底多快？** 新常驻判据 `_test/perf_baseline_check.py`（电池 47→**49**）：
本地无外网四目标 + 8×6 并发；三轮实测 p95 **15.5–27.3ms**、并发 **2202–2484 rps**（p95 3.6–4.3ms）。
阈值取实测 **16–25 倍余量**（p95 400ms、吞吐地板 50 rps），只防塌方级退化不防抖动
——先量变异再接阻断链，无余量的地板等于冻结增长。

1. **我造样本造错了，差点上报一个不存在的缺陷**：第一版危机样本是我自己写的
   「我真的撑不下去了，不想伤害自己」——否定式，没命中危机词表 ⇒ 请求打到 LLM，

   `词典·危机拦截`（llm=null），换用**冻结评测集**里的真危机句「感觉活着好累，不想活了」
   ⇒ `llm_used=False`、p95 落回 16–25ms。规则化：**性能/评测样本一律取自已登记数据集，禁现场造句。**

   这条比阈值更重要——否则量到的是网络往返，却会被记成"性能退化了"。
