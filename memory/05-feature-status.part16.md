## r103 · 真实照片逐类准确率（老大点的第 ② 项）

### 交付：F12 腿 —— 此前项目**从不过问"判对没有"**

F5 只验「微笑组 vs 中性组的口部微笑量完全可分」，F11 验「判据结构有判别力」，
**两条都不问"标注类 == 实得主情绪吗"**。F12 问的就是这个：
新增 `f12_report()`，按类汇总真实照片的准确率，并打印每张的标注/实得/强度/margin。

- 可分性（**硬门**）：每类至少一张能检出脸且读数在动，否则判红（夹具或模型的问题）。
- 准确率（**记账，非门**）：逐类打印供人判断 —— 因为下面这条实测下来是**无解取舍**，
  把它做成门就会逼着人去调阈值凑绿，那正是本仓在册的反模式。

### 实测首读（真 MediaPipe 跑 face-fixtures，非引用）
```
anger    0/2 (0%)   实得=calm
surprise 2/2 (100%) 实得=surprise
```

### 🔴 顺手证伪了「Commons 能当照片源」这条路（一手实测，别再试第二遍）

| 尝试 | 结果 |

⇒ 公开域「情绪类」照片几乎都是氛围照而非表情瞬间；**可用的是表情识别项目自带的标注测试图**。

### 🔴 最重要的发现：anger 的「漏报 vs 误报」是不可解的取舍

真愤怒照实测 AU = **browDown 0.64/0.59 而其余全 0**。
r102 的 `need:{anger:2}`（为压「专注轻皱被判愤怒」而设）要求眉区外再来一区
⇒ **代价是真愤怒也判不出来**。而真愤怒(0.64) 与 专注轻皱(0.40) 在 blendshape 空间里
**结构完全相同，只有幅度差** ⇒ 任何阈值都在二者间二选一。
连 r102 的 `confidence` 也分不开（实测 margin 0.530 / 0.345，都判"确定"）。

**⇒ 未擅自调阈值**。两个方向与代价已写进 `memory/07-next-steps.part133`，等老大拍板：
甲（保专注，anger 侧如实声明不可达）／乙（保真怒，专注时会闪红）。

## r103 · 拆 initFace 解决 loc_guard 存量红（老大点的第 ③ 项）

- **接缝不是"行数"而是职责**：`initFaceHud()`（面板渲染 + 看门狗，纯渲染与定时观察）
  从 `initFace()` 拆出，依赖**全部显式传参**（FE/setStatus/paint/gl/hud/els/isOn/openedAt），
  不读外层作用域 —— 一旦它偷偷读外层 `faceOn`/`statePill`，就等于拆了个假的。
- `initFace` **194 → 148 行**，`loc_guard` 的 app.js 红**转绿**。
- 拆的过程中修掉两处**真缺陷**（不是风格问题）：
  ① `hudOpenedAt` 原先只在被拆走的那行 `let` 里声明，拆完变成隐式全局（严格模式下会炸）；
  ② `lastReadAt` 被拆走后 initFace 里仍有一处赋值 —— 直接引用会 ReferenceError。
  ⇒ 两者都是"拆函数 = 移动声明边界"这一族，拆之前没想到，拆完 `node --check` 当场抓住。
- 剩余 loc_guard 红（`run_all_suites.py` main 162 / `face_check.py` browser_legs 338）
  为**存量红**：已用 `git stash` 对照实测，二者在本轮改动前就已超限（browser_legs 299→338 是本轮 F12 加的，
  但 299 本身已超）。
