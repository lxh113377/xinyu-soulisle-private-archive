## 五、验证方案

|---|---|---|---|

### 5.2 量化指标（每轮写 10-core-capabilities 轨迹表）

- **主指标**：有把握帧（confidence≥on）top-1 准确率 **≥95%**；不确定帧占比 **≤30%**。
- **抗干扰**：极端场景（暗光 bright<0.16 / 侧脸 yaw>0.36 / 嘴部遮挡）错误率较基线 **降 ≥50%**
  （基线 = S4 首跑读数，先量后改）。
- **延迟**：单帧 blendshape→读数 p95 **≤100ms**；表情跳变→界面更新端到端 **≤500ms**
  （EMA 收敛按 α 与采样率折算，埋点实测量化）。
- **红线指标**：crisis 恒 false 不受影响；隐私零网络请求（face 链路不发出任何请求）。

### 5.3 灰度验证策略

1. **本地**：fat jar + `?faceRules=shadow` 双跑（新旧规则同帧各算一次，控制台对比分布，不上线）。
2. **灰度发布**：deploy/xinyu 副本以 URL 参数 `?faceRules=v3` 启用新规则（默认仍 v2），
   收集 3~5 天反馈后切默认；切默认 = 改 src 默认值 → 走完整发版链（r49 三件套：逐文件 hash → M 归属 → 回读）。
3. **回退**：参数切回 v2 即时生效；代码级回滚 = revert 对应 commit（独立 commit 前提）。

## 六、质量标准（老大 r124 定版）

| 维度 | 标准 | 判据 |
|---|---|---|
| 常规场景准确率 | **有把握帧 top-1 ≥95%**（置信度达标帧） | S4 尺子复算 |
| 敢说不确定 | 不确定帧 ≤30%，且不确定不冒充确定 | margin 机制 + 三态文案 |
| 极端场景 | 识别错误率较基线 **降 ≥50%** | 分场景对账 |
| 延迟 | 单帧 p95 ≤100ms 且端到端 ≤500ms | 埋点统计 |
| 不劣化项 | crisis 恒 false / 零网络 / 单测 31/31 → 只升 | core_capability_baseline |

## 七、风险预案

- **R1 动态分母放大单帧噪声**（误报升）→ 兜底三件：cue.min 门 / margin 置信 / face_discrim 回归；
  若三项后误报仍升 ⇒ 该机制改"软分母"（激活 AU 权重下限 0.3），不动回滚整体。
- **R2 anger 加 browInnerUp 负权误伤真愤怒**（真怒 AU4+AU1 可能共存）→ 负权 ≤0.5 起步，
  标定取"专注可分离"的最小值；标注集里真愤怒用例先行验证再合入。
- **R3 标注集偏见**（公开数据集 FER2013 演员脸 vs 真人低强度分布差异）→ 自录样本 ≥30%；
  分场景分层统计，禁止只报总体准确率。
- **R4 隐私合规**（照片/人脸数据）→ 仓内只存 52 维 AU 向量；照片留标注者本机；
  公网链路零请求（现有红线，判据 public_check）。
- **R5 部署副本漂移**（改了 src 忘 deploy）→ deploy_sync_check.py 三类归零是发布前置（既有红线）。
- **R6 混合派/模型派预案的隐性成本**（本轮未授权）→ 触发即重跑 F1 vendor sha256 四件套 +
  隐私论证 + 模型体积预算；不在本轮排期。
- **R7 并发撞车**（本仓 49 个在途 M）→ 只碰本文档族与 rules/engine 执行轮显式 --file 提交；
  Edit 锚点未命中即停手重读，禁猜。
