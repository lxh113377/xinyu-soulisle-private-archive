# 卷43 — r48 窄屏能力入口面（上）：「一键点亮怎么没了」的实测归因（2026-09-27）

> 下卷 `part44`：新判据口径 + 首跑双向自证 + 两条未闭环。触发：老大报障；裁定：**样式不动，只补判据**。

## 1. 实测结论（非推测）

功能三处全在：`src/index.html:101` 按钮 / `src/js/app.js:101` handler /
`src/js/three-scene.js:211` `lightShow()`；部署副本 `deploy/xinyu/` 同步在位。
消失源 = `src/css/style.css` 的 `@media(max-width:480px){#btn-lightshow{display:none}}`
（commit `6cae042`，2026-09-24 对标轮 M6「响应式扩到 480/768/1024」，**行上无注释**；部署副本同规则）。
逐档实测（playwright 打 8123 真页面，读计算样式与盒）：
**481px display:block 87x27 ｜ 480px display:none 盒 0x0 ｜ 479px 同上**。
480 以下**无任何替代入口**：全页仅 app.js 一处调用 `lightShow`。
⇒ 现象成立且非"功能被删"：手机评委打开站点看不到演示这一屏，而所有既有判据仍是绿的。

## 2. 为什么既有判据**结构性**抓不到（不是它们写错）

- `_test/lightshow_check.py` 视口固定 1280x800 ⇒ AC-OBS-04 恒绿，窄屏路径从未被量过；
- `_test/mobile_check.py`（r47 在飞）M2 口径是「所有**可见**交互目标 ≥44x44」，
  且自带反例⑦「隐藏元素不得判（display:none 不算缺陷）」
  ⇒ 「由可见变不可见」的入口对它天然豁免，永远不会红。
  实证：它首跑抓到 `btn-lightshow 87x27` 来自 **768 档**；320/360/390 三档该按钮根本不在读数里。

## 3. 分诊依据（R245：承诺的行为 vs 意外的缺陷）

`display:none` 这条**是**刻意的（M6 响应式收坞标题条空间），但**代价没被承诺过**——
行上无注释、无替代入口、无任何判据盯住，所以"能力在手机上不可达"属意外面。
老大裁定「只补判据不改样式」⇒ 本轮按**设计内取舍 + 代价挂账**处置：
样式零改动，缺陷面转为常驻判据盯住，代价进豁免账并写明撤账条件（见下卷 §5）。
